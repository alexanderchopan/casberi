Why this beats both earlier answers

Against v2 (the rail): same information, 410pt cheaper. The rail spent a column to buy alignment; the overline gets the same single left edge for free, because when no column is reserved there is nothing to indent past. And five-across returns, which is the rhythm the strip, the catalog tiles and today's tray all share.

Against alphabetizing today's grid: alphabetical keeps the height but breaks the tray's job as the strip's map — it would teach positions the icon-only strip doesn't have. This keeps the frozen order inside every group, adds the category read on top, and still comes in 18pt shorter than the flat grid it replaces.

The ruling it needs: packing floats the singletons out of catalog order (Work sits in row one). If catalog order must be strict, the same layout packs to five rows / ~660pt — a one-row price for a faithful sequence. Either way no scroll bar at twenty sources; the layout crosses the 620pt resting cap only past roughly thirty.

Icons are simplified stand-ins; a build uses the same BridgeIcon marks. Rings read as they do on the strip — solid tint is where you are, dashed orange (Farcaster above) is a connection that needs you.
