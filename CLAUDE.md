# Casberi

Native iOS app — a personal corpus of "things" (links, screenshots, events, chats, voice notes, agent outputs) with on-device generative UI synthesis. Solo project, pre-App Store (Developer Program enrollment active; shipping via TestFlight, App Store v1 not yet submitted).

## Repository & working directory (RULE)

- **The canonical working copy is `~/Developer/casberi` — NOT iCloud Drive.** Always work here. The old iCloud copy (`.../myStuff/product/casberi`) is deprecated; do not edit it.
- Backed by a **PUBLIC** GitHub remote `origin` → https://github.com/alexanderchopan/casberi (public by the user's choice, confirmed 2026-08-02 — this doc said "private" until then, which was wrong). Two things follow, both load-bearing: **every commit is world-readable the moment it lands** (the auto-push below is immediate), so nothing secret may EVER be committed — real keys live in the macOS login Keychain via `scripts/dev-keys.sh`, and the only credentials in-tree are ones that are safe in public by design (the Reown/WalletConnect project id, a Dropbox app key — both public identifiers, not secrets); and Actions minutes/storage are FREE for public repos, so nothing here counts against the account's Actions allowance. A `post-commit` hook auto-pushes to `origin` in the background on every commit (off-site backup) — so `git commit` alone keeps the backup current; a manual `git push` is only needed if a push failed while offline (see `.git/last-autopush.log`). Commit workflow is unchanged otherwise: solo, straight to `main`, no branches/PRs required. Note: committing/pushing to `main` is NOT a release — releasing is the separate archive+upload step (`scripts/testflight.sh`).

## Layout

- `Casberi/Casberi.xcodeproj` — the Xcode project. Targets: **Casberi** (app), **ShareExtension** (appex), **CasberiWidgets** (widget bundle). Bundle id `com.casberi.app`; app group `group.com.casberi.app`.
- `Casberi/Casberi/` — app sources (`Design/`, `GenUI/`, `Model/`, `Screens/`, `Shell/`).
- `Casberi/Shared/` — sources compiled into both app and extension targets.
- `docs/` — **build-brief.md §8 (design system) is law**; prd.md carries product rulings; name-ledger.md.
- `prototype/` — visual spec. `design/app-icon/` — icon SVG sources.
- The pbxproj is **hand-authored** (objectVersion 77, file-system-synchronized groups). New source files in synced folders are picked up automatically; Info.plist keys and target settings are edited directly in the pbxproj.

## Building (critical)

From the canonical `~/Developer/casberi` copy, a plain build codesigns cleanly — no workaround needed:

```sh
xcodebuild -project Casberi/Casberi.xcodeproj -scheme Casberi \
  -destination 'platform=iOS Simulator,name=iPhone 17 Pro' build
```

Or just run `scripts/verify.sh` (build + install + screen sweep + answer probe).

- **Mac parity gate (`verify.sh` step 1b, 2026-08-12):** after the iOS build, `verify.sh` COMPILES Mac Catalyst and hard-fails on any error. Until this landed the pass built iOS Simulator alone, so a mobile change that broke Catalyst went out green and was caught only by `verify-mac.sh` — a **LaunchAgent driving a real GUI app, so a closed lid means the night is SKIPPED, not queued** — or by a failing archive at ship time. Twenty-two files carry a `#if targetEnvironment(macCatalyst)` branch no iOS build ever compiles, and the ReownAppKit `platformFilter = ios` in the pbxproj (without it Catalyst dies on `'NSColor' is not a member type of class 'ReownAppKit.AppKit'`, measured 2026-08-01) is one careless project edit from gone with nothing else asserting it. **COMPILE ONLY, and that ceiling is the point** — it proves the Mac still BUILDS, never that it still WORKS; running it stays `verify-mac.sh`'s job and none of that script's plumbing transfers. Its OWN derivedData (`CasberiCatalystDD`), never `$DD`: a shared dir makes the two builds evict each other's module cache so every pass goes cold. Gates on xcodebuild's own exit, not on a bundle existing (verify-mac's 2026-08-01 lesson — an incremental dir keeps yesterday's bundle around). **Deliberately NOT spelled `xcodebuild … | grep error:` the way `verify-mac.sh` spells it**: that script runs `set -uo pipefail` and this one `set -euo pipefail`, so there a SUCCESSFUL build is what kills the run — grep matches nothing, exits 1, pipefail hands it to `set -e`. Measured 2026-08-12: **101s cold from an empty dir, 72s warm** (the warm number is the per-run cost). `SKIP_CATALYST=1` skips it, the `LAUNCH_CYCLES=0` hatch; it sits BEFORE the `--build-only` exit, so that flag is now a both-platform compile gate. Proven able to fail, since a check that cannot fail proves nothing: a `#if targetEnvironment(macCatalyst)` type error builds iOS clean (exit 0, 0 errors) while this goes red — green on iOS, broken on Mac, the entire class it exists for.
- **Mac parity audit (`scripts/mac-parity-audit.py`, 2026-08-12):** the drift a Catalyst COMPILE cannot see, and the answer to "must I flag new features for Mac parity" — **no**. Static, self-tested (11 fixtures), in `verify.sh`; `verify-mac.sh` picks it up with no line of its own, because it is named `*-audit.py` and that script now discovers. **(1) Swept screens** — every `case "<host>"` in `RootShell.route(_:)` is a screen a deep link reaches, so both sweeps must open it or it goes in `KNOWN_UNSWEPT` with a reason. Found on its first run that **`casberi://settings` was swept on the Mac and never on iOS**: the screen carrying the privacy copy, the sync toggle and both delete verbs had no iOS screenshot in any automated pass (fixed by sweeping it, not exempting it). - **The Mac verify's cleanup is BOUNDED, and that bound is a fix not a precaution (2026-08-02):** its last act deletes the per-PID scratch stores inside `~/Library/Containers/com.casberi.app/Data/tmp`, which is TCC-protected. Under launchd that delete is denied and skipped — the behaviour the old comment described — but from an interactive or automation shell **TCC does not return an error, it BLOCKS**, waiting on a consent decision that never arrives. Measured: a run sat there **39 minutes** with every gate already passed, all five screenshots and four probe logs written, and the perf-history row already appended, so it read from outside as a failed verification when nothing had failed; the `SUMMARY` line `nightly-mac.sh` parses never printed. Three things the fix had to get right, each learned by measuring: (1) a plain timeout around `rm` is NOT enough — a bare `ls` of that path blocks too, and the `casberi-scratch-*` GLOB must read the directory to expand, so the parent shell hangs before `rm` is reached; the whole statement, glob included, runs inside the bounded child. (2) macOS ships no `timeout(1)`, so the watchdog is spelled out (background job + `sleep`-then-`kill -9`). (3) The glob needs zsh's `(N)` qualifier: without it a non-matching glob is an ERROR ("no matches found") whose exit code is indistinguishable from the watchdog's kill, and the first cut of this fix reported "TCC blocked it" on a machine that simply had nothing left to clean — only a signal death (`> 128`) is the hang. **Corollary for reading a stalled run:** check `scripts/output/perf-history-mac.csv` for a row at the current SHA and `scripts/output/mac-<ts>/` for the 5 PNGs + 4 `probe-*.log` files — if those exist every gate passed. ## Simulator gotchas

- Typing via computer-use `type` triggers the macOS accent-picker. Instead: `printf "text" | xcrun simctl pbcopy booted`, then cmd+a, Delete, cmd+v.
- Sim switches don't respond to computer-use clicks — drag across the knob.
- Dynamic Type: `xcrun simctl ui booted content_size` (underscore).
- Launch args do NOT trigger `onOpenURL` — use the `-deeplink` hook below, or `xcrun simctl openurl booted casberi://...`.
- Computer-use approval is blocked in scheduled/non-interactive runs — drive the app via launch-arg hooks + `simctl` there.
- Installing for probes: pick the NEWEST DerivedData (`ls -dt ~/Library/Developer/Xcode/DerivedData/Casberi-*` — plain `ls -d` is alphabetical and served a day-old binary for 30 minutes on 2026-07-14). `runAll` NSLogs `probeArgs:` with the launch args it saw — if that line is missing or stale, you're running the wrong binary.
- **`booted` is ambiguous with two simulators up** (2026-07-21): a second Claude session boots its own device, and from that moment every `xcrun simctl … booted` (install, launch, screenshot) may resolve to THEIR device — as can computer-use/simulator-MCP taps, which pick the frontmost. The symptom reads as a stale build: your new strings are in the binary, the screen shows the old UI, and the app randomly leaves the foreground (they terminated it). Pin the udid on every call (`xcrun simctl list devices booted` to get it, then `xcrun simctl launch <udid> …` and the simulator tool's own `udid:` argument) the moment a second device appears.
- **Verify the INSTALLED binary, not just the newest one** (2026-07-16): `ls -dt` globs across EVERY `Casberi-*` DerivedData dir, so when a second Claude session is building concurrently it can serve you THEIR app — which silently lacks your probe hooks. The symptom is maddening: `probeArgs:` logs your args correctly, and the hooks just never fire (they're absent from the binary, so `string(forKey:)` finds nothing to match). Three runs were misdiagnosed as rate limits and regressions before this was spotted. Check the bundle you actually installed: `strings "$(xcrun simctl get_app_container booted com.casberi.app app)/Casberi" | grep -c '^myHookKey$'` — 1 means it's really there. Concurrent sessions also share one build DB (`database is locked` → just retry until it clears).
- On a fresh sim install the demo seeds re-ask Photos/Calendar/Health permission at launch, and the queued sheets block everything (probes still run, but the UI is unusable and Health's ask stalls its probe). Pre-grant what simctl can (`xcrun simctl privacy booted grant photos com.casberi.app` — AFTER install; uninstall wipes grants) and tap the Health sheet once via computer-use; grants then persist for every later headless run.

It draws EVERY published deadline, not just the listed rows. **The end-padding mutation SURVIVED the harness's first run** — the assertions checked ordering and bounds and never the pad, so a dot at either extreme would have rendered as a half-moon clipped by its own track with every test green. **UNVERIFIED and structurally so**: no simulator can show a tinted Home Screen (`.vibrant`), a Smart Stack rotation (the relevance scores) or a configured widget's picker, so all three are reasoned about and compiled, never seen.

## SwiftUI/UIKit gotchas already paid for

- **A quick action is REGISTERED on the app delegate and DELIVERED to the scene delegate (prd §377, 2026-08-14).** `application(_:performActionFor:completionHandler:)` is the pre-scene door and UIKit does not call it in a scene-based app — which every SwiftUI `App` is; the action goes to `windowScene(_:performActionFor:)`, and a COLD launch arrives as `UIScene.ConnectionOptions.shortcutItem`, never in `launchOptions`. The "Daily Brief" long-press shipped 2026-08-03 with only the app-delegate handler and **could not have worked on any launch**: the `brief.request` flag was never written, so the app finished opening the way it always opens — the All feed, which is exactly how it was reported. **It looked healthy because registering and handling are different delegates**: `didFinishLaunchingWithOptions` does fire, so the item appeared with its title and icon and opened the app. `Shell/QuickActions.swift` owns both doors now (`SceneDelegate` installed via `application(_:configurationForConnecting:options:)`, which also reads `options.shortcutItem` itself as the cold-launch belt and braces). **The flag and the `QuickAction.received` notification are not redundant** — the flag is durable (a cold launch has no `RootShell` listening yet), the notification is immediate (on a warm delivery `handleActivation` may already have run, and it is debounced to one pass per two seconds, so a flag with no nudge raises the brief on some LATER foreground the person meant for something else). Both call `openBriefIfRequested`, which guards on the flag, so only the first one does the work. **Not reachable by any harness here** — the compiler is happy with a callback nobody calls, the audits are static, and no simulator gesture can long-press a Home Screen icon; `-quickActionProbe YES` exercises the in-process landing (and says in its own comment that a pass is not evidence the delivery works), the delivery half is a device check. Standing lesson: for any UIKit hook that concerns the SCENE — quick actions, state restoration, cold-launch URL/activity continuation — check which delegate the current lifecycle delivers it to before writing the handler; getting it wrong fails silently, and silent here reads as "the app opened normally".
- A background layer BEHIND a NavigationStack never shows through (opaque UIKit backing). Page backgrounds paint INSIDE each screen: `.dsPageBackground()` on the scroll container; List also needs `.scrollContentBackground(.hidden)`.
- **A feed ROW never carries a presentation of its own — one screen, one `.sheet` (third time paid for, 2026-07-28).** `FeedScreen` presents through exactly ONE `.sheet(item: $feedSheet)` (`FeedSheetRoute`) because five sibling `.sheet` modifiers on the screen made the first tap silently self-dismiss. The same rule reaches DOWN the tree: a `.sheet` attached to a view INSIDE a `List` row resolves to the same presenting UIViewController, so the row's tap starts the thing sheet and the row's own sheet modifier tears it back down mid-transition — the sheet rises PART WAY and closes again. Cause: the 2026-07-27 social pass moved `ReplyingToRow` and `SocialQuoteCard` — both `Button` + `.sheet(isPresented:)`, correct inside `ThingSheetView`, which is itself a presented sheet — into `PostCard`/`SocialThreadCard`, i.e. into feed rows. THE RULE: a row is a read with ONE gesture (tap → the thing sheet, ruling 2026-07-16); anything walkable inside it renders as context (`allowsHitTesting(false)`), and the walk lives in the sheet, which routes through its own single presentation (`ThingSheetView.walkingTo`). - **An `NLEmbedding` is not safe to call from two threads at once — ONE INFERENCE AT A TIME, process-wide (build 281, 2026-08-07).** Shipped and crashed on device: `EXC_BAD_ACCESS` at `0x2000` with **two threads inside `CoreNLP::SentenceEmbedding::fillStringVector` simultaneously** — the main thread on `RootShell.handleActivation` → `KeptAskStore.refreshDigests` → `KeptAskComposers.search` → `Retriever.rank` → `EmbeddingIndex.queryVector`, and the cooperative pool on `EmbeddingIndex.packedVectors`'s detached utility task. `EmbeddingIndex.modelLock` guarded the model CACHE and nothing guarded the model, so both threads got the same shared object and called `vector(for:)` into it concurrently. **This was not a rare interleaving — it is what the design asks for on every single foreground**: the inference was deliberately moved off the main actor (see `indexPending`'s own comment) so it wouldn't block, and moving it off is exactly what made it concurrent with a query side that never left main. **PROVEN, not inferred**: four threads hammering one shared model died **3/3** unlocked (SIGSEGV/SIGTRAP) and survived 12,000 inferences **3/3** with a lock. THE RULE: every `NLEmbedding` compute call (`vector(for:)`, `neighbors(for:)`, `distance`) goes through `EmbeddingIndex.serialized { }`. **ONE gate for EVERY model, not one per instance** — both crashing stacks bottomed out in the same `CoreNLP::ContextualWordEmbedding::fillWordVectors`, which the sentence AND word embeddings share, so per-object locking would leave the cross-object case (`SemanticExpand.neighbors` against a sentence `vector`) wide open. **A SERIAL QUEUE, not an `NSLock` — the first cut of this fix used a lock and traded the crash for a FREEZE.** A mutex is not fair: the backfill, looping a 32-text batch, releases and instantly re-acquires, barging past a main thread already waiting. Measured on one workload — uncontended **1.6ms** median / 3.3ms max; NSLock **13–43ms** median, **p95 280–347ms, max 2573ms**; serial FIFO queue **5.5ms** median, p95 6.5–12ms, **max 15ms**. A 2.5-second main-thread stall is a worse bug than the crash, and it would land on the very foreground path this app is already fighting for smoothness. `modelLock` is released before the queue is entered, so the two are never held together and there is no lock order to get wrong. Mechanical in `ondevice-selftest.sh` (mutation-tested three ways, incl. build 281's exact line) — and its negative sweep reads a **comment-stripped** copy, because the source documents this rule by naming the very methods it governs, so a guard grepping raw source fires on the prose explaining it (the Obsidian/Cursor lesson, earned again here on this guard's first run). **Why no other check could see it**: `xcodebuild` is happy, the audits are static, and the simulator ships no on-device model — so every model path runs its unavailable branch there and a sim sweep exercises none of them. **Two reports, and the PAIR is the proof**: builds 280 and 281 crashed the same way on different binaries, with both threads at the same Casberi offset in each (`+2595796`, then `+2592912`) and the faulting thread and the survivor SWAPPED between them — which is what a symmetric race looks like, and why neither side is "the" culprit. **281 also renames the bug**: it died **131 seconds** after launch, so "crashes on open" was the reporter's symptom and not its shape — `runForegroundWork` runs on every activation and `indexPending` loops until the store drains, so on a large or freshly-synced corpus the sweep embeds for minutes and any ask in that stretch races it. **And it reads exactly like the SwiftData liveness class above without being it** — no SwiftData frame, no `_assertionFailure`, no `ForEachChild`. Read the frames the report actually names before reaching for the audit you remember.

## Design law (read docs/build-brief.md §8 before UI work)

- Trays are NEVER hand-rolled — use `DSTray(title:height:)` (`Design/DSTray.swift`).
- Liquid Glass on the floating layer only (composer/FAB/toasts) — never on content. (The tab bar was dropped in `0764ee3` (2026-07-13): one surface now, a source-chip header + a FAB, no tabs. Ruling: prd §100 (recorded 2026-07-17). Older PRD rulings — §16, the store/onboarding batches, §61's amended elevation-law example — still narrate a tab bar; those are historical ledger entries, true when written, deliberately NOT rewritten; read them against §100. The chip header itself led with a "Pinned" chip/board until that retired 2026-07-20 (prd §131) — it now leads with "All"; the FAB is the agent's own rise/lower bar, not the old board's.)
- No letter-spacing, no ALL-CAPS eyebrows — headers are words in sentence case ("Getting started", never "G E T T I N G  S T A R T E D" or "GETTING STARTED"). `.kerning()` is banned; the type ramp carries hierarchy by size/weight alone (ruling 2026-07-08).
- No hairlines — zero exceptions (2026-07-10: the Apps page's CONNECTED strip and its divider died; the catalog is one grid where connected tiles wear state and open management). Nothing draws a line. Widget/tile radius = `DS.Radius.widget`.
- Apps Browse categories follow prd §59 (2026-07-11): X browses under **Social** (with Bluesky, Farcaster, Telegram) — a social account first, not a saves source; Slack browses under **Work** (with GitHub, Linear, Notion) — a workplace tool, not a messenger; and **Notes** is its own category (Apple Notes, Day One, Apple Journal, Obsidian) — the vault is notes, not project tracking. Taxonomy lives in `Model/BridgeCatalog.swift`; website Browse sections mirror it in the same session.
- Typed text in the composer NEVER saves — things enter only via capture paths (paste chip, mic, share, screenshots, drop, bridges). Saving is an outcome the toast reports, never a verb.
- Swipe verbs are reads only (writes live in the sheet, with consent). Feed chips only when they differentiate.
- Honesty rule: no dead controls, no fake status. Three corollaries the 2026-07-16 audit paid for (prd §83): a hand-rolled button that paints its own background MUST swap that background when disabled — `.disabled` dims a plain-style button's label, not your background, so it reads live while inert (prefer `BridgeFieldRow`); never quote a price off a stale last trade — quote the live book's own bracket midpoint, or show nothing (an empty bid-0/ask-1 book is the one bracket that says nothing; its midpoint would invent a 50% coin flip), and read both sides of a delta the same way; and a change that rounds to zero has no direction — no sign, no green/red (`TokenChartStyle.isFlat` / `accent(change:)`). The iCloud-sync ship gate is MET (2026-07-07): CloudKit capability is in the build, voice audio rides the store (externalStorage → CKAsset), Delete everything purges the CloudKit zone, and only the app process mirrors (extensions use `SharedStore.extensionContainer()`). "End-to-end encrypted" claims still require Advanced Data Protection — don't overclaim.
- Product rulings live in docs/prd.md — check it before re-litigating a design decision; record new rulings there.

- **RULE (user, 2026-07-31): a new bridge is not done until its API hosts are in the "What this app reaches" registry** (`Model/NetworkReach.swift`, prd §205) — the privacy screen that makes "no server, nothing routes through us" checkable rather than merely claimed. Enforced by `scripts/network-reach-audit.sh` (runs in `verify.sh`, static, no build): every host literal in the app must appear EITHER in that registry OR in the audit's explicit non-reach denylist (permalink/display hosts the person's own browser opens on tap, setup doors a connect screen opens, demo placeholders). An entry names the SERVICE, its `reach` (`.always` / `.whenConnected(bridge:)` / `.onTap`), a plain-words `purpose` saying what the request carries, and the hosts. **This is a ship gate, not a nicety**: a bridge whose host nobody disclosed makes the app's own privacy screen quietly wrong, and a TestFlight build is on testers' devices before anyone notices. Shipped as exactly that failure on 2026-07-31 — the Stripe pass ran `catalog-sync.sh` and the liveness audit BY HAND, both green, and never invoked the reach audit, so `api.stripe.com` went out in build 214 undisclosed. **The lesson is mechanical, not moral: run `scripts/verify.sh`, not the audits you happen to remember** (`LAUNCH_CYCLES=0` skips only the slow relaunch loop, never the static head). **A host BUILT at runtime is not a host literal (prd §289, 2026-08-03)** — the audit's regex matched nothing at all in `"https://\(chain.network)…"`, so five per-chain Alchemy RPC hosts reached on every wallet sweep went undisclosed for the wallet's whole life, and the RECEIPTS screen found them, not the audit. Two checks now cover it: interpolated forms must name a declared family (coarse — it could not have caught this alone, since `api.g.alchemy.com` shares the tail), and every `Chain(network:)` in `WalletIngest`'s own table must have its `<network>.g.alchemy.com` in the registry. The other half of the class can never be declared: a host that comes from the PERSON's input (a followed feed, a Shopify store, a self-hosted PostHog, a saved link). Those call sites name their service to `NetworkLedger.record(host:as:)` instead — do that for any new bridge whose host is typed rather than fixed, or its rows read as undisclosed reaches on the receipts screen. See docs/testflight-handoff.md step 3.
- RULE (user, 2026-07-08): website icons are ALWAYS inlined as base64 data URIs in `website/index.html` — NEVER hot-link an external `<img src="https://cdn.simpleicons.org/…">` (or any remote image host). External icon hotlinks intermittently render as blank slots when the CDN hiccups / is rate-limited / is ad-blocked. To add an icon: fetch it from `cdn.simpleicons.org/<name>/ffffff` (or wherever), then inline the bytes as `data:image/svg+xml;base64,…` (or PNG base64). Every `<img>` on the site must be self-contained; there should be zero remote image requests.
