# Casberi

Native iOS app — a personal corpus of "things" (links, screenshots, events, chats, voice notes, agent outputs) with on-device generative UI synthesis. Solo project, pre-App Store (Developer Program enrollment active; shipping via TestFlight, App Store v1 not yet submitted).

## Repository & working directory (RULE)

- **The canonical working copy is `~/Developer/casberi` — NOT iCloud Drive.** Always work here. The old iCloud copy (`.../myStuff/product/casberi`) is deprecated; do not edit it.
- Backed by a private GitHub remote `origin` → https://github.com/alexanderchopan/casberi. A `post-commit` hook auto-pushes to `origin` in the background on every commit (off-site backup) — so `git commit` alone keeps the backup current; a manual `git push` is only needed if a push failed while offline (see `.git/last-autopush.log`). Commit workflow is unchanged otherwise: solo, straight to `main`, no branches/PRs required. Note: committing/pushing to `main` is NOT a release — releasing is the separate archive+upload step (`scripts/testflight.sh`).

## Layout

- `Casberi/Casberi.xcodeproj` — the Xcode project. Targets: **Casberi** (app), **ShareExtension** (appex), **CasberiWidgets** (widget bundle). Bundle id `com.casberi.app`; app group `group.com.casberi.app`.
- `Casberi/Casberi/` — app sources (`Design/`, `GenUI/`, `Model/`, `Screens/`, `Shell/`).
- `Casberi/Shared/` — sources compiled into both app and extension targets.
- `docs/` — **build-brief.md §8 (design system) is law**; prd.md carries product rulings; name-ledger.md.
- `prototype/` — visual spec. `design/app-icon/` — icon SVG sources.
- The pbxproj is **hand-authored** (objectVersion 77, file-system-synchronized groups). New source files in synced folders are picked up automatically; Info.plist keys and target settings are edited directly in the pbxproj.

## Building (critical)

From the canonical `~/Developer/casberi` copy, a plain build codesigns cleanly — no workaround needed:

```sh
xcodebuild -project Casberi/Casberi.xcodeproj -scheme Casberi \
  -destination 'platform=iOS Simulator,name=iPhone 17 Pro' build
```

Or just run `scripts/verify.sh` (build + install + screen sweep + answer probe).

- **SwiftData liveness audit (`scripts/swiftdata-liveness-audit.py`, 2026-07-25):** the "never read a dead Thing" rule (see the ForEach/`isLive` gotcha below) made MECHANICAL instead of remembered — it was written down after build 139 and re-broken twice anyway, costing builds 142 and 150. Two checks: a `ForEach` over a DERIVED thing array (including an inline chain off a `@Query`, e.g. `ForEach(things.filter { … })`) must go through `.keyed`; and a `Thing` held in `@State` whose STORED property is read in that file must be guarded by `isLive`/`.live`. Runs FIRST in `verify.sh` (static, no build). Its `--self-test` runs before the audit itself and is not optional decoration: a check that can't fail proves nothing, so it demonstrates it catches each shape (derived, chained, held) and passes the clean ones before it certifies the tree. The stored-property set is parsed out of `Shared/Thing.swift` at run time, so a new `@Model` field is covered the day it lands. `KNOWN_UNGUARDED` is the escape hatch — adding a file is a conscious "no stored property of a held Thing is ever read here."
- **Keychain policy audit (`scripts/keychain-audit.py`, 2026-08-02, prd §277):** every `SecItemAdd` in the app must set a `kSecAttrAccessible…ThisDeviceOnly` policy AND name `kSecAttrSynchronizable`. Static, self-tested, runs in `verify.sh`/`verify-mac.sh`. Mechanical because the failure is INVISIBLE — a key stored `AfterFirstUnlock` (no `ThisDeviceOnly`) works perfectly, reads back fine, and also rides an encrypted backup onto whatever device restores it; nothing in a build or a screen sweep can see that. File-scoped rather than call-scoped on purpose (pairing a `SecItemAdd` with the dictionary literal built ten lines earlier means parsing Swift, and a file that writes secrets without ever naming a device-only policy is the finding either way). `KNOWN_EXEMPT` is empty by design — an entry is a conscious "this secret may survive a backup restore." Note accessibility is fixed at ADD time, so hardening the code is only half the fix: `TokenVault.migrateToDeviceOnly()` re-writes existing items (migration v5) and `-keychainProbe YES` prints the before/after census.
- **Secret-scan self-test (`scripts/secret-scan-selftest.py`, 2026-08-02, prd §277):** the credential tripwire's fixtures — that the shipped patterns still hide a recovery phrase and still leave an ordinary shopping list alone. Reads the regexes, thresholds and BIP39 wordlist OUT of `Model/SecretScan.swift` + `Model/SecretScanWordlist.swift` (never a copy), runs 28 fixtures and a mutation pass proving each threshold is load-bearing. It MIRRORS the algorithm (Luhn, the run scan) in Python and says so in its own header — it cannot execute Swift, so it proves the patterns classify as designed, NOT that the app compiles or that its control flow matches. **The thresholds are measured, don't re-tune from intuition:** ordinary prose tops out at a 2–3 word BIP39 run, but a shopping list measured 12 consecutive wordlist words and a list of common verbs 19, so run length alone would redact people's lists; a real phrase wrapped in wallet chrome measured only 47% density, so density alone would miss it. Two rules, either sufficient, each covering the other's blind spot.
- **Live-integrations heartbeat (`scripts/live-integrations.sh`, 2026-07-17):** a SEPARATE keyless host-liveness check — do the public RPCs still serve the prepare/approval fee+receipt methods (`eth_gasPrice`/`eth_estimateGas`/`eth_getTransactionReceipt`), does Peer's orchestrator still emit `IntentFulfilled` fills on Base, do the keyless discovery APIs (Dexscreener/GeckoTerminal/Jupiter/Bluesky) still 200. Catches DEPENDENCY DRIFT, the one class `verify.sh` (all-local, deterministic) can't see. Contract, do not break: WARN-ONLY (always `exit 0` — a third-party hiccup must never fail a build), and ZERO Alchemy credits (every request is keyless; the credit-spending `alchemy_getTokenMetadata`/Portfolio calls stay in the IN-APP pre-release probes — `-peerProbe`/`-approvalProbe`/`-prepareProbe`, which land real things and DO spend credits). Do NOT fold it into `verify.sh` (breaks its deterministic contract) and do NOT add a keyed check to it. Fine for scheduled/non-interactive runs (curl-only, no sim/computer-use).

- **Perf pass (`scripts/perf.sh`, prd §257):** one cold launch, three tracked metrics (launch init→ready, steady RSS, answer latency) appended to `scripts/output/perf-history.csv`, plus a **span breakdown** naming where the launch time went. REPORTS, never gates (`exit 0` always). Two things to know before using it: (1) **the first launch after `simctl install` is not a data point** — the store re-opens cold (`containerWithFallback` measured 506ms vs 53–150ms settled), so run it twice and read the second; (2) the numbers are DEBUG (`-Onone`) and therefore an upper bound — pass `-launchTimer YES` to a **Release** build to time the configuration people actually run (`LaunchClock.reports`; Release measured ~350ms against Debug's ~477ms the same day). The span markers (`LaunchPerf`) are DEBUG-only and free in release. Standing lesson from §257, worth more than any single number: for three weeks this pass recorded a launch climbing 293ms → 763ms and could not say why, because its log predicate dropped the very markers the app was emitting — **a metric with no breakdown tells you to panic, not what to do.**
- **Mac verify (`scripts/verify-mac.sh`, 2026-08-01):** the ONLY pass that runs the Mac Catalyst build as an app rather than compiling it — build → cold-launch survival → 5-screen sweep → 4 deterministic on-device probes (answer/find/today/intent) → keyless live probes (warn-only) → perf, into `scripts/output/mac-<ts>/` with its own `perf-history-mac.csv`. Every Mac TestFlight build from 178 to 203 shipped on `xcodebuild succeeded` alone; this exists so that stops being true. **None of `verify.sh`'s plumbing transfers** — Mac Catalyst is a real macOS process, not a simulator guest — and each substitution is measured, not assumed: `simctl launch` → **`open -n`** (launching the binary directly runs the process but the UI NEVER mounts — no first frame, ever); `log stream` → **`open --stderr`** (unified logging captured ZERO lines from an `open`-ed Catalyst app; the same NSLogs land on stderr); `simctl io screenshot` → **the app screenshots itself** (`-macSnapshot`, since `screencapture` needs a Screen Recording grant a headless nightly can't click through). Two DEBUG-only hooks carry it: `-macSnapshot <name>` (renders the key window to the container tmp, NSLogs the path — **the log line is the contract, not a guessed path**) and `-storeScratch YES` (**load-bearing**: on the sim the guest sandbox isolates a run for free, but on the Mac a DEBUG build shares the REAL app-group container with the installed app, so without it a run whose schema is ahead forward-migrates your daily driver's corpus and every probe heals/deletes real things). Three traps it already paid for, each a check that would otherwise pass while measuring nothing: `casberi://home` and `casberi://feed` are the SAME screen since the tab bar died (two byte-identical PNGs counted as two screens — the feed shot is seeded now so it proves rows render); the answer metric on an empty corpus logged **15ms** because the model never ran, and would have "improved" on any retrieval regression (seeded: ~1.0–3.2s); and the span breakdown printed `  ms over  calls` because `feedList[All]`'s brackets are a grep character class (`-F`). **Perf ratios are deliberately looser than `verify.sh`'s** (200/150/250 vs 140/140/160) — four back-to-back runs of identical code measured launch 190–400ms and answer 1021–3194ms, so at the iOS ratios every night flags a REGRESSION, and a nightly that always warns is a nightly nobody reads.
- **Mac nightly (`scripts/nightly-mac.sh` + `scripts/com.casberi.nightly-mac.plist`):** the unattended wrapper — one row per night in `scripts/output/nightly-mac.log` (verdict + the three perf numbers + the run dir), 14-night pruning, 10 launch cycles. Install with `cp scripts/com.casberi.nightly-mac.plist ~/Library/LaunchAgents/ && launchctl bootstrap gui/$UID ~/Library/LaunchAgents/com.casberi.nightly-mac.plist`; run on demand with `launchctl kickstart -p gui/$UID/com.casberi.nightly-mac`. A **LaunchAgent, not a Daemon or a cloud runner** — it drives a real GUI app and needs the logged-in window server, so a closed lid means the night is SKIPPED, not queued. The plist runs it under `zsh -lc` because a LaunchAgent otherwise inherits a minimal PATH and dies on "xcodebuild: not found" with no other symptom. The verdict is parsed from `verify-mac.sh`'s machine-readable `SUMMARY` line, NOT by counting `⚠` in the console: the perf section prints that character for flags it raises by design and never gates on, and counting them scored a perfectly clean night as `PASS(5warn)` on the wrapper's first run. Live warnings (a third party was unreachable) and perf flags (a number moved) are different things and stay separate; `SKIP_LIVE=1` is recorded too, so a row with three checks skipped can't read as a full pass.
- **iCloud copy only (deprecated):** building inside the iCloud folder **fails codesign** ("resource fork, Finder information, or similar detritus not allowed"; `com.apple.provenance` xattrs are SIP-protected). There, add `-derivedDataPath "$HOME/Library/Developer/CasberiDD"`. Not needed from `~/Developer/casberi`.

- Test device: **iPhone 17 Pro** simulator, iOS 26 runtime.
- FoundationModels (on-device LLM) is iOS 26-only at **runtime** — `#if canImport` is not enough, use `if #available(iOS 26.0, *)`. `@Generable` schema types MUST be file-scope (nesting one in a private enum emits broken keypaths → heap corruption crashing on unrelated threads).
- There is currently **no test target** — the GenParser tests from early sessions were never persisted. If adding tests, create a proper unit-test target.
- **Schema versioning (RULE, 2026-07-15):** `Casberi/Shared/ThingSchemaVersioning.swift` holds `ThingSchemaV1`/`ThingMigrationPlan`. A purely additive `Thing` change (new optional property, a new `@Attribute` on an existing property) needs nothing — SwiftData infers it. A BREAKING change (rename, type change, a removed property) needs a new `ThingSchemaVN` + a `.lightweight` migration stage there — CloudKit mirroring supports lightweight migration only, so a change that can't be expressed that way isn't a migration-plan problem, it's a new-field-plus-backfill problem. Skipping this on a breaking change no longer crash-loops installs (`SharedStore.containerWithFallback()` degrades to CloudKit-off, then in-memory, instead of `CasberiApp`'s old `fatalError`) — but a real migration is still the right fix; the fallback is a safety net, not a substitute.
- **CloudKit Production is a SEPARATE ship (RULE, 2026-08-01) — see docs/cloudkit-deploy.md.** "SwiftData infers it" above is true of the STORE and says nothing about CloudKit: Development auto-creates a new field the first time a dev build syncs it, **Production never does**, and TestFlight/App Store builds mirror to Production. An undeployed field doesn't fail loudly — CoreData exports only non-nil attributes, so plain notes sync while every voice note, social post and screenshot silently fails its export forever. Nothing in the build or `verify.sh` can see this. So a new `Thing` property isn't shipped until it's in Production: update Development with `xcrun cktool import-schema`, then promote in the CloudKit Console (`cktool` refuses every production write by design). Found 20 fields behind on 2026-08-01, undetected because no shipped iOS build had the iCloud entitlement at all, so Production sync had never once run.

## Simulator gotchas

- Typing via computer-use `type` triggers the macOS accent-picker. Instead: `printf "text" | xcrun simctl pbcopy booted`, then cmd+a, Delete, cmd+v.
- Sim switches don't respond to computer-use clicks — drag across the knob.
- Dynamic Type: `xcrun simctl ui booted content_size` (underscore).
- Launch args do NOT trigger `onOpenURL` — use the `-deeplink` hook below, or `xcrun simctl openurl booted casberi://...`.
- Computer-use approval is blocked in scheduled/non-interactive runs — drive the app via launch-arg hooks + `simctl` there.
- Installing for probes: pick the NEWEST DerivedData (`ls -dt ~/Library/Developer/Xcode/DerivedData/Casberi-*` — plain `ls -d` is alphabetical and served a day-old binary for 30 minutes on 2026-07-14). `runAll` NSLogs `probeArgs:` with the launch args it saw — if that line is missing or stale, you're running the wrong binary.
- **`booted` is ambiguous with two simulators up** (2026-07-21): a second Claude session boots its own device, and from that moment every `xcrun simctl … booted` (install, launch, screenshot) may resolve to THEIR device — as can computer-use/simulator-MCP taps, which pick the frontmost. The symptom reads as a stale build: your new strings are in the binary, the screen shows the old UI, and the app randomly leaves the foreground (they terminated it). Pin the udid on every call (`xcrun simctl list devices booted` to get it, then `xcrun simctl launch <udid> …` and the simulator tool's own `udid:` argument) the moment a second device appears.
- **Verify the INSTALLED binary, not just the newest one** (2026-07-16): `ls -dt` globs across EVERY `Casberi-*` DerivedData dir, so when a second Claude session is building concurrently it can serve you THEIR app — which silently lacks your probe hooks. The symptom is maddening: `probeArgs:` logs your args correctly, and the hooks just never fire (they're absent from the binary, so `string(forKey:)` finds nothing to match). Three runs were misdiagnosed as rate limits and regressions before this was spotted. Check the bundle you actually installed: `strings "$(xcrun simctl get_app_container booted com.casberi.app app)/Casberi" | grep -c '^myHookKey$'` — 1 means it's really there. Concurrent sessions also share one build DB (`database is locked` → just retry until it clears).
- On a fresh sim install the demo seeds re-ask Photos/Calendar/Health permission at launch, and the queued sheets block everything (probes still run, but the UI is unusable and Health's ask stalls its probe). Pre-grant what simctl can (`xcrun simctl privacy booted grant photos com.casberi.app` — AFTER install; uninstall wipes grants) and tap the Health sheet once via computer-use; grants then persist for every later headless run.

## Dev keys (real secrets for keyed probes)

- Real test keys for keyed probes (`-byokKey`, `-tokenBridge`, `-openSeaKey`, …) live in the macOS login Keychain under service `casberi-dev.<name>`, managed by `scripts/dev-keys.sh` (`set` prompts silently or reads stdin — the user stores once; `get`/`list`/`delete`). **RULE (user, 2026-07-16): fetch a key ONLY inline via command substitution** — e.g. `xcrun simctl launch booted com.casberi.app -byokKey "venice:$(scripts/dev-keys.sh get venice)"` — never `get` into echo/cat/a variable you print, so values never enter assistant context or session transcripts. `scripts/dev-keys.sh list` shows what's available (names only). This replaces asking the user to paste keys per session; if a needed key isn't stored, ask them to run `dev-keys.sh set <name>` once.

## DEBUG launch-arg hooks

All read via UserDefaults in `Shell/RootShell.swift` unless noted:

- `-deeplink <casberi://url>` — open a deep link on launch.
- `-chipStats "<source:n[,…]>"|clear` — seed the source strip's tap-learning counters (`Model/ChipMemory.swift`): a chip you actually visit sorts ahead of pure most-recent-first, decaying back over a week of neglect. Every `MainSurface` mount NSLogs `chipLabels:` with the computed order, so a promotion verifies in one launch.
- `-openThing "<title prefix>"` — open the newest thing whose title starts with the prefix (the sheet-by-content route for headless sheet checks; a UUID changes every install, a title doesn't). NSLogs `openThing:` with the match. Runs at mount, BEFORE async ingest/seed hooks land anything — on a fresh install or when pairing with an ingest probe, launch once to land, then relaunch with `-openThing`.
- `-answerProbe "<query>"` — run the answer path headless, NSLog the result (`-probeDelay <s>` to wait first).
- `-uiAnswerProbe "<query>"` — auto-open the composer and send through the real UI path (also read in `Shell/Composer.swift`).
- `-mcpProbe "<query>"` — MCP probe.
- `-noPrewarm` — skip model session prewarm.
- `-fresh YES|NO` — sticky new-user mode (persists until flipped or reinstall); re-shows onboarding.
- `-accountDetail <case>` — open a settings detail sheet (`Screens/AccountScreen.swift`).
- `-openSettings YES` — pushes the settings screen (`HomeRoute.shared.present(.settings)` in Home's onAppear). Reliable again since the `HomeRoute.path`-array rewrite (2026-07-22, see the `navigationDestination(item:)` gotcha below) — `MainSurface` reads `route.path` directly on every body evaluation instead of an edge-triggered item binding, so an early push landing before the stack mounts renders on the first frame with no re-landing dance. `-deeplink casberi://settings` still works too, both routes are equally reliable now.
- `-icloud.sync YES` — AppStorage override for the sync toggle copy.
- `-onboarded YES` — AppStorage override that skips first-launch onboarding (fresh installs otherwise land on it, hiding the screen you deep-linked to).
- `-pileTap "<Offer name>"` — fire an empty-feed pile tile's tap after the fall (the tile → product-page arc, headless; NSLogs "pileTap:"). The empty feed (2026-07-16) is the display headline + catalog pill + the settled pile of app tiles (`EmptyFeedPile` in `Screens/FeedScreen.swift`; its `pileApps` array is catalog-sync-checked like the marquees). Staging an empty feed takes TWO launches: `-fresh YES -onboarded YES` first (fresh re-shows onboarding over the feed regardless of the override; terminate it), then relaunch `-onboarded YES` — sticky fresh keeps the corpus empty and the cover stays down.
- `-openApp "<Offer name>"` — open a store product page; `-openSetup "<Offer name>"` — push a bridge's setup screen (both need `casberi://account` opened after launch); `-openProject "<Tag>"` — push a project detail (`Screens/AccountScreen.swift` / `HomeScreen.swift`).
- `-theme.light 0|1` — AppStorage theme override; always pass explicitly for light/dark screenshots (the sim's stored value sticks).
- `-startPick folder|wallet|follow|catalog` / `-startFollow "<Bluesky|Farcaster|Feed>:<name>"` — walk the ONBOARDING FORK headlessly (prd §217, `Screens/StartHereScreen.swift`). Onboarding is TWO screens now: the unchanged "How it works" greeting, whose CTA is **"Try it"** and pushes the fork, then "What should I start with?" — three cards covering the three real audiences (your own files / a wallet / someone to follow). Pair as `-fresh YES -howItWorksCTA 2 -startPick <arm>`. Each arm NSLogs `startPick:`, then `startFolder: <n> in|unreadable`/`startPick: wallet`/`startFollow: <net> <name> → <n> in`. **The first card swapped from "Show me my screenshots" to "Show me my files" on 2026-07-28** — a stronger first proof (any real folder, not just the screenshot library) that reads as "this app can hold anything," not one narrow category; screenshots ingest is unchanged and still reachable from the catalog. It rides the Files bridge (`Model/FilesBridge.swift`) via the system folder picker (`fileImporter`), which — like every other document-picker/sign-in hop in this app — **can't be driven headless**: `-startPick folder` only opens the picker. `-startFolder <path>` bypasses the picker entirely and connects a folder by path directly (`setFolder` → `FilesIngest.refresh` → `store.registerConnected`), NSLogging `startFolder:` with the landed count — the only way to exercise the actual landing path headlessly. Wallet hands off to the wallet manager (which already IS "enter an ENS, paste an address, or connect your wallet app"); follow pushes a segmented Bluesky/Farcaster/Feed form (`-startFollow` splits on the FIRST colon so a feed URL keeps its own). **Tripwire (prd §217): the moment a fork card grows a toggle it is the connect screen §96 deleted, and should be deleted again** — these are verbs with visible outcomes, not sources with switches.
- `-howItWorksCTA <s>` — fire the onboarding greeting's "Try it" CTA after a delay (`Screens/HowItWorksSheet.swift`; NSLogs "howItWorksCTA: fired" and pushes the FORK — it landed in the Apps catalog before §217). Onboarding is ONE screen since 2026-07-16 (prd 96): the connect screen and its `-demoPick` hook are DELETED — the "How it works" greeting carries the icon rain itself and its CTA is the whole arc, so `-fresh YES -howItWorksCTA <s>` walks onboarding headless alone. Do NOT pass `-onboarded NO` when probing the CTA landing — the argument domain masks the CTA's `onboarded = true` write for the whole run, so the cover reads as never dismissing; `defaults delete com.casberi.app onboarded` (app terminated) instead. Naming ruling (user, 2026-07-16): user-facing copy never calls the Apps surface a "store" — it's "the catalog".
- `-findProbe "<query>"` — fill the composer and fire **Find** (prd §215, the composer's deterministic door): runs `KeptAskComposers.search` → `Retriever.rank` and NSLogs `findProbe:` (query + the keepable kind) plus one `findDoc|` line PER doc line. Find is NOT the Ask button relabelled — no model is reached, nothing is synthesized, and the badge says "Matched on this iPhone — nothing was written"; a `findDoc|` dump carrying `Row(...)` entries and no prose IS that promise as a test. The chip leads the typed-draft band for ANY draft (a question included — "climate links" and "what did I save about climate?" are the same search to the retriever), while "Send to" keeps its old rule and sits out for a question. A paste offers no Find (a capture path on its way to being kept). The result is keepable straight into the `search:<query>` kind that already existed. One NSLog per line on purpose — a joined multi-line message gets truncated by the log reader (the `-todayProbe` lesson).
- `-openComposer YES` — open the composer empty (screenshots the ask chips); `-composerDraft "<text>"` — pre-fill the field on open (read in `Shell/Composer.swift`; reaches the typed state's "Open in" chips — the tool-tile grid and its `-forceTools` hook died 2026-07-16, prd 90); `-linkTitleProbe <url>` — NSLog the fetched page title; `-askStats "<key>:<n>[,…]|clear"` — seed the ask tiles' tap-learning decay counters (prd 95, `Model/AskMemory.swift`: an ask offered 10 opens untapped sorts behind the next qualifier; a tap resets it; seeded once per launch, self-guarded). Keys are MEMORY keys: the kind ("week", "pulse"), or kind:qualifier where one kind wears many faces ("showtag:recipes", "context:Photos"). Every composer open NSLogs `askTiles:` with the chosen keys, so demotion verifies in one launch (seed `pulse:12`, watch `pulse` move last). Opens that hand off an ask (chrome.askRequest) don't count as offers.
- `-oembedProbe <url>` — ask an allowlisted host what a saved link IS, keylessly (prd §244, `Model/OEmbed.swift`), and NSLog every field it answered with: provider/author/thumbnail, then the title and the `enrichedText` the link would land wearing (three NSLogs, not one — the `-todayProbe` truncation lesson). Reads `handled=NO` when the host isn't in the table and `FAILED` when it is and the endpoint didn't answer — different bugs, so they read differently. This is link ENRICHMENT, not a bridge: nothing connects, nothing syncs, there is no catalog seat and `catalog-sync.sh` has nothing to check. It exists because the generic path (`LinkTitle.enrich` → `ProductMeta`/`fetchPage`) reads a page's `<head>`, and some sites serve a non-browser client no usable head at all — a TikTok link used to land wearing the site's stock page title with no thumbnail and no creator, while every other link in the corpus got a real face. `OEmbed.endpoints` is an ALLOWLIST by design (TikTok/YouTube/Vimeo/SoundCloud/Spotify/Flickr): the spec's `<link rel="alternate" type="application/json+oembed">` discovery would need the page fetch this path exists to beat, and would let any saved URL name an arbitrary host for us to call. Host matching is on the label boundary (`== suffix` or `.hasSuffix("." + suffix)`), never `contains` — `tiktok.com.attacker.example` must not match. A hit RETURNS from `enrich` rather than falling through, or the page fetch would overwrite the good title with the stock one. **UNMEASURED (2026-07-31): authored on Linux with no Xcode and no egress to any of these hosts — never compiled, never run.** Every endpoint is doc-derived and every failure path returns nil to the existing behaviour, so it fails safe; probe each host before trusting it. Why TikTok gets this and not a seat: their export is 1–4 days stale (declined, prd §36, unchanged), they have never had RSS (the generators are scraped, the Duolingo decline), the Display API reads only the authenticated account's own posts, and the EEA Data Portability API needs the post-M2 server.
- Kept asks (docs/agent-brief.md rulings 1/4/5/13, `Model/KeptAskStore.swift`, `Model/KeptAskComposers.swift`) — the agent's own standing-question chips, always deterministic (never the model). `-keepAskProbe "<kind>:<title>"` keeps a kind headlessly (`clear` empties the store) — splits on the LAST colon (fixed 2026-07-20), since a compound kind carries its own (`showtag:Book club`, `context:Calendar`, `search:design links`). Kinds: `away`, `wallet`, `watchlist`, `overdue`, `noticed` (tile-only, no typed trigger), `showtag:<any tag>`, `context:<any connected source>` ("what's new in Calendar?"), `search:<query>` (any free-text ask that actually retrieved something — re-runs `Model/Retriever.swift`'s deterministic engine, painting matches, never re-synthesizing the original prose). `-agentThingProbe "<title prefix>"` pushes the agent's Stack straight to a real thing's drill-down headlessly (mirrors `-openThing`, title not UUID). `-askStats "<key>:<n>[,…]|clear"` — seed the ask tiles' tap-learning decay counters (prd 95, `Model/AskMemory.swift`: an ask offered 10 opens untapped sorts behind the next qualifier; a tap resets it). A KEPT pill shares these same counters (2026-07-20) and decay-DIMS instead of demoting, since it can't be sorted away. `-asksMade "<key>:<n>[,…]|clear"` — seed the INVERSE counter (how often an ask is actually made, not ignored): at `AskMemory.mintThreshold` (3) the answer's quiet "Keep" pill upgrades to a prominent "You ask this a lot — keep it?" prompt, same action underneath. Every composer open NSLogs `askTiles:` with the chosen suggestion keys, so demotion verifies in one launch (seed `pulse:12`, watch `pulse` move last). ## SwiftUI/UIKit gotchas already paid for

- A background layer BEHIND a NavigationStack never shows through (opaque UIKit backing). Page backgrounds paint INSIDE each screen: `.dsPageBackground()` on the scroll container; List also needs `.scrollContentBackground(.hidden)`.
- **A feed ROW never carries a presentation of its own — one screen, one `.sheet` (third time paid for, 2026-07-28).** `FeedScreen` presents through exactly ONE `.sheet(item: $feedSheet)` (`FeedSheetRoute`) because five sibling `.sheet` modifiers on the screen made the first tap silently self-dismiss. The same rule reaches DOWN the tree: a `.sheet` attached to a view INSIDE a `List` row resolves to the same presenting UIViewController, so the row's tap starts the thing sheet and the row's own sheet modifier tears it back down mid-transition — the sheet rises PART WAY and closes again. Symptom, user-reported: "opening fc feed items doesn't work, it opens half way and closes". Cause: the 2026-07-27 social pass moved `ReplyingToRow` and `SocialQuoteCard` — both `Button` + `.sheet(isPresented:)`, correct inside `ThingSheetView`, which is itself a presented sheet — into `PostCard`/`SocialThreadCard`, i.e. into feed rows. Farcaster wore it worst because nearly every cast it lands has a parent or a quote (channel casts, mentions and likes are mostly replies), so nearly every fc row grew the extra sheet. THE RULE: a row is a read with ONE gesture (tap → the thing sheet, ruling 2026-07-16); anything walkable inside it renders as context (`allowsHitTesting(false)`), and the walk lives in the sheet, which routes through its own single presentation (`ThingSheetView.walkingTo`). A component used in BOTH places takes a flag (`SocialQuoteCard.walkable`) rather than presenting unconditionally.
- **Decorative motion during a refresh must be CoreAnimation, not SwiftUI** (2026-07-28, user: "the rain pour always lags on pages"). SwiftUI interpolates `.offset`/`.opacity` per frame on the MAIN actor — and every ingest in this app is `@MainActor` (inserts/deletes on the main context, each re-emitting the feed's `@Query`), so a pull-to-refresh delight animates in exactly the window where the main thread is least able to draw it. It stuttered by construction, every time. `Design/BerryRain.swift` now deals `CALayer` circles with a `CAAnimationGroup` (position + opacity, `beginTime` for the stagger, `.backwards` fill), which the render server drives out of process — smooth while the main thread is blocked solid. Corollary from the same fix: ONE gesture deals ONE shower. `refreshFeed()` bumped `chrome.refreshPulse` a second time a few ms after `.refreshable` already had, re-dealing the in-flight drops over the same identities.
- `UIGraphicsImageRenderer` defaults to device scale (3×) — pin `format.scale = 1` for downscale renders.
- A bare `Image().resizable().scaledToFill()` in a ZStack expands the ZStack to image size — pin in GeometryReader + `.clipped()`.
- A child `.gesture(DragGesture)` beats ScrollView vertical scroll entirely on device — use native `swipeActions`, never custom swipe DragGestures in scroll content.
- Silent `try?` on EventKit (and similar) writes swallows denials — surface outcomes via `ShellChrome.flash()`.
- A SwiftData `#Predicate<Thing> { $0.tags.contains(x) }` (`tags` is a transformable `[String]` attribute) COMPILES clean but crashes at RUNTIME — EXC_BAD_ACCESS/SIGSEGV inside CoreData's `_NSCoreDataStringSearch` mid-SQLite-fetch (found 2026-07-21 scoping `ProjectDetailScreen`'s `@Query` to a project's tag as a perf win; reproduced by opening a project, confirmed via crash report, reverted). Plain string-equality predicates (`$0.source == source`) are fine and already used throughout `Model/IngestSupport.swift` — the crash is specific to `.contains` on an array-typed attribute, which SwiftData can't safely push down to SQL here. Filter tag membership in Swift AFTER an unscoped fetch instead; don't reintroduce a tags-array predicate without verifying against a real on-device fetch first.
- **Never key a `ForEach` on a persistent `@Model` property from a DERIVED array — the perpetual "crashes on different screens after an update/first sync" class (builds 137/138/139, 2026-07-24).** Reading any stored `Thing` property (`id`, `title`, `source`, `capturedAt`, …) after that `Thing` is deleted/invalidated traps inside SwiftData (`_assertionFailure` → EXC_BREAKPOINT, stack: `ForEachChild.updateValue()` → Casberi → SwiftData). SwiftUI re-reads each element's `id` during identity diffing on EVERY graph update, including the exact transaction a delete lands. The app deletes `Thing`s constantly on the MAIN context while the UI is live: `SyncReconcile.dedupeBySourceRef` at launch (collapses CloudKit-merged duplicates) + a per-foreground heal in nearly every bridge (Photos/Calendar/Reminders/Contacts/HomeKit/OneClaw/Bluesky/Farcaster/Mail — each `context.delete`s upstream-gone rows), plus CloudKit-propagated deletes. A `ForEach` **directly over a `@Query` array is coordinated by SwiftData and safe**; a `ForEach` over a `.filter`/`.map`/day-grouping/`@State`-held array holding raw `Thing` refs is NOT — that derived case is the whole crash surface, and it recurs on every screen that has one (feed, wallet Worth-a-look tray, wallet history, Tokens/Stocktwits/Kalshi watchlists, address-book card, the shared `RecentThingsSection`). THE RULE: iterate `things.keyed` (`Screens/ThingRowKeying.swift` — a `KeyedThing` value wrapper capturing `id.uuidString` while the model is valid) and read `$0.thing` in the body; an enum row type must store its id (`case approval(id: String, thing: Thing)`), never compute it from `t.id` lazily. For a HELD reference (a `Thing` in `@State`, captured in a closure, or bound to `sheet(item:)`/`navigationDestination`) guard with `thing.isLive` (same file) before reading a stored property, since a delete can land under an open sheet/dialog. A fresh install is NOT immune — it still imports the iCloud zone (duplicates and all) then dedupes them. This is NOT the SwiftUI "reused id" trap (that asserts in SwiftUICore with no SwiftData frames). COROLLARY (build 142, 2026-07-24): the guard for the HELD case must not `dismiss()` from `onAppear`. `ThingSheetView`'s `if thing.modelContext == nil { Color.clear.onAppear { dismiss() } }` converted the SwiftData read-trap into a UIKit crash — dismissing DURING the sheet's (zoom) present transition trips `brk 1` inside `-[UIPresentationController runTransitionForCurrentStateAnimated:]` (reached via SwiftUI `SheetBridge.preferencesDidChange`; the empty branch also drops the `.presentationDetents` the sheet expects, which pokes `preferencesDidChange`). COROLLARY 2 (build 150, 2026-07-25): **keying the `ForEach` is only half the fix — anything else that reads the same derived array is still exposed.** A pull-to-refresh crash symbolicated (`atos` against the archive dSYM) to `FeedScreen.countLabel` inside `daySection`'s own SECTION HEADER: the rows were correctly keyed, but the header did `Set(rows.map(\.kind))` over the raw day-grouped array, and `cardRunPositions` read `standsAlone(rows[$0])`/`rows[$0].id` beside it. A refresh runs every bridge's heal, so a delete lands inside the same graph update that re-evaluates the section, and the first persisted read on a tombstoned model traps — same `_assertionFailure` → SwiftData → Casberi stack, no `ForEachChild` frame needed on the Casberi side. THE RULE: filter a derived array to `filter(\.isLive)` ONCE at the top of the view that owns it, before positions, rows, headers or footers read through it — and guard shared helpers that take `[Thing]` (like `countLabel`, called from both a header and the caught-up footer) independently, since their other call sites hand them their own derived arrays. **COROLLARY 3 (build 176, 2026-07-28): keying and pre-filtering are BOTH insufficient — the row body itself must re-check.** `ForEachChild.updateValue()` re-evaluates the CONTENT closure against the array the `ForEach` value ALREADY HOLDS, under its own `ObservationCenter` callback, when a tracked model changes — the parent body has not re-run yet, so that array still contains the row just deleted. So the upstream `filter(\.isLive)` of corollary 2 is not a guard for the body: it ran when the view value was made, which is BEFORE the delete. Build 176 crashed on first open exactly there — day rows correctly keyed (`FeedRow.id` a captured `String`), header correctly filtered, checks 1 and 2 both green — trapping one frame later on `thing.kind` inside `FeedScreen.shapedRow`. THE RULE: a `ForEach` content closure re-checks liveness INSIDE the closure before its first stored-property read — `if let thing = row.live { … }` (`KeyedThing.live`) — and that includes reads in the ARGUMENTS of a row-builder call (`imageOnly.contains(thing.id)`), which are evaluated at the call site and therefore beat any guard the builder does internally. Now mechanical: the liveness audit's CHECK 3 flags a content closure that reaches `.thing` with no `isLive`/`.live` inside it (mutation-tested against build 176's own crash site). Its deliberate limit — it triggers on `.thing`, so a `Thing` bound out of another wrapper is invisible — is why `FeedScreen.FeedRow.single` carries a `KeyedThing` rather than a raw `Thing`: keep new row wrappers in the shape the lint can see. Two duplication traps this crash paid for: `FeedScreen` had a PRIVATE copy of `KeyedThing` that shadowed the shared one and never gained `live` (now deleted, one type), and its doc asserted the false premise ("bodies only ever render the post-delete `@Query` snapshot") that made the whole class look solved. **COROLLARY 4 (build 177, 2026-07-28) — the ROOT the other three were symptoms of: do not hand a held `[Thing]` onward on the PROMISE that downstream readers guard.** Build 177 crashed with no `ForEach` frame at all — `FeedScreen.feedList` → `List.init(content:)` → `themesLedeSection` → `HomeComposition.projectClusters` reading `thing.tags`. The source is `visible`, which for the unfiltered All room returns `debouncedAllSnapshot` (`@State private var … : [Thing]?`, the 2026-07-28 perf debounce) — raw model refs held across a debounce window, so DELIBERATELY behind the live corpus: not a narrow race but a window that stays open after every delete. The comment above that property claimed "every downstream reader already re-filters `.isLive`"; that was never true, and both 176 and 177 are the same stale array reaching two different unguarded readers. THE RULE: filter `.live` AT THE BOUNDARY — the computed property or accessor that hands the array out (`visible`, `merged`, `orderedWatched`) — so the guarantee is local and provable, not a cross-file promise; and guard SHARED helpers that take `[Thing]` internally too (`for thing in things where thing.isLive`), since they're reached from several callers. Mechanical as CHECK 4: a `@State`-held `[Thing]`/`[Thing]?` returned or passed onward whole without `.live` is a finding (verified against build 177's own line). It is deliberately narrow — hand-off only, one finding per array, comments stripped and shadowing rebinds skipped, since its first draft fired 15 times on one screen — with a documented `HANDOFF_OK` escape hatch for the one case where filtering would misalign `IndexSet` offsets. Note a shadowing rebind (`let posts = posts.live`) HIDES the guard from the audit: spell `.live` per use instead. Two audit defects this found: `GenUI/` was never in `SOURCES` at all (the crash file lives there), and CHECK 3's `.thing` trigger matched `.thingID` as a substring (now `\.thing\b`). **COROLLARY 5 (build 188, 2026-07-29) — THE LEAF, and the deepest form of the class: corollaries 1–4 are all about the CONTAINER, and a container guard only stops a dead row being CREATED.** SwiftUI re-evaluates a leaf view's body on the MODEL'S OWN observation through that leaf's own attribute node (`DynamicBody.updateValue` → `ViewBodyAccessor.updateBody`), with no involvement from the parent that built it — so a row ALREADY in the tree is untouched by anything the parent does. Build 188 crashed there with no `ForEach` and no `List` frame: `BandRow.body` → `mailSender` → `thing.kind`, re-run inside a `UICollectionView` batch update while the source pager animated (`PagingCollectionView.apply(changes:)` → `_UIHostingView.layoutSubviews`). Keying was right, the ForEach-closure guard was right, the boundary filter was right, and **none of them were in the crash path**. THE RULE: a `View` struct that stores a `Thing` guards its OWN body — `var body: some View { if thing.isLive { liveBody } }` with the original body renamed to `@ViewBuilder private var liveBody` (no re-indenting, and no extra view-tree depth since it's a computed property, not a wrapper view). This was ALREADY the build-142 lesson recorded above ("guard the sheet's CHILD views … the parent's guard doesn't cover a child SwiftUI re-renders on the model's own observation") — scoped to two sheet views and never generalised to the **25** row/content views that had the identical shape (`BandRow`, `TokenRow`, `PostCard`, `PhotoWell`, every `ThingContent`/`ThingStage` view, `WalletHistoryRow`, `LiveStreamHero`, …), all now guarded. Mechanical as CHECK 5: a `struct X: View` with a stored `Thing` property and no `isLive`/`.live` anywhere in the struct is a finding (mutation-tested — it names `ShapedRows.swift:20 BandRow`, 188's own crash site). Read the whole corollary chain together: 3 and 4 are about who hands the model over, 5 is about who reads it, and 5 is the one that holds when the parent isn't running at all.

SUPERSEDED 2026-07-22: `HomeRoute` no longer uses `navigationDestination(item:)` at all. ## Design law (read docs/build-brief.md §8 before UI work)

- Trays are NEVER hand-rolled — use `DSTray(title:height:)` (`Design/DSTray.swift`).
- Liquid Glass on the floating layer only (composer/FAB/toasts) — never on content. (The tab bar was dropped in `0764ee3` (2026-07-13): one surface now, a source-chip header + a FAB, no tabs. Ruling: prd §100 (recorded 2026-07-17). Older PRD rulings — §16, the store/onboarding batches, §61's amended elevation-law example — still narrate a tab bar; those are historical ledger entries, true when written, deliberately NOT rewritten; read them against §100. The chip header itself led with a "Pinned" chip/board until that retired 2026-07-20 (prd §131) — it now leads with "All"; the FAB is the agent's own rise/lower bar, not the old board's.)
- No letter-spacing, no ALL-CAPS eyebrows — headers are words in sentence case ("Getting started", never "G E T T I N G  S T A R T E D" or "GETTING STARTED"). `.kerning()` is banned; the type ramp carries hierarchy by size/weight alone (ruling 2026-07-08).
- No hairlines — zero exceptions (2026-07-10: the Apps page's CONNECTED strip and its divider died; the catalog is one grid where connected tiles wear state and open management). Nothing draws a line. Widget/tile radius = `DS.Radius.widget`.
- Apps Browse categories follow prd §59 (2026-07-11): X browses under **Social** (with Bluesky, Farcaster, Telegram) — a social account first, not a saves source; Slack browses under **Work** (with GitHub, Linear, Notion) — a workplace tool, not a messenger; and **Notes** is its own category (Apple Notes, Day One, Apple Journal, Obsidian) — the vault is notes, not project tracking. Taxonomy lives in `Model/BridgeCatalog.swift`; website Browse sections mirror it in the same session.
- Typed text in the composer NEVER saves — things enter only via capture paths (paste chip, mic, share, screenshots, drop, bridges). Saving is an outcome the toast reports, never a verb.
- Swipe verbs are reads only (writes live in the sheet, with consent). Feed chips only when they differentiate.
- Honesty rule: no dead controls, no fake status. Three corollaries the 2026-07-16 audit paid for (prd §83): a hand-rolled button that paints its own background MUST swap that background when disabled — `.disabled` dims a plain-style button's label, not your background, so it reads live while inert (prefer `BridgeFieldRow`); never quote a price off a stale last trade — quote the live book's own bracket midpoint, or show nothing (an empty bid-0/ask-1 book is the one bracket that says nothing; its midpoint would invent a 50% coin flip), and read both sides of a delta the same way; and a change that rounds to zero has no direction — no sign, no green/red (`TokenChartStyle.isFlat` / `accent(change:)`). The iCloud-sync ship gate is MET (2026-07-07): CloudKit capability is in the build, voice audio rides the store (externalStorage → CKAsset), Delete everything purges the CloudKit zone, and only the app process mirrors (extensions use `SharedStore.extensionContainer()`). "End-to-end encrypted" claims still require Advanced Data Protection — don't overclaim.
- Product rulings live in docs/prd.md — check it before re-litigating a design decision; record new rulings there.
