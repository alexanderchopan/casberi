Casberi · the wallet manager pattern, generalized

One ledger grammar for every watch-list

The wallet manager stopped being a settings page by doing three things: identity leads, one omnibox both adds and searches, plumbing demotes to a door. The same three moves fit Farcaster, Bluesky, RSS, Substack, Reddit, YouTube, Podcasts, Tokens and Stocktwits — every bridge that manages a set you WATCH rather than a login you set once. The clean line: faces you watch → roster shelf; topics and assets → ledger. So Farcaster/Bluesky become the wallet screen exactly — a roster of people up top, a ledger of topics below — while RSS, Tokens and Stocktwits (which carry URLs and prices, not faces) stay pure ledger. Below: the grammar on the three surface families, to rule on once and inherit nine times.

My read, and the calls for your ruling

RULE 1 · THE OMNIBOXOne field, find-or-add

Farcaster's people field and channel field become one, with a leading / as the topic route — matching how people already write channels. Same for Bluesky (people + feed search in one). Typing filters your watched set live, exactly like the wallet omnibox filters the book. Ask: is the / grammar right, or should topics stay a second field?

RULE 2 · MARK GRAMMARRound is a person, square is a topic

The wallet already draws faces round, machinery square (AddressMark). Extending it: channels, feeds, and RSS publications become square marks — an instant person-vs-topic read down the whole ledger, unified app-wide. Today channels/feeds render as circles. Ask: ratify square-for-topic as a standing rule (I'll record it in prd)?

RULE 3 · PEOPLE GET A ROSTERFaces shelf, topics ledger

Watched Farcaster/Bluesky accounts ride a face roster exactly like the wallet's — unbounded, so no dashed cap-slots, just one trailing "+". Everything per-account (likes/mentions, watch-their-wallet, who-they-follow) moves behind the row tap → SocialProfileCard, which already hosts all three. Topics (channels/feeds) stay the square-mark ledger. Ask: roster for people, ledger for topics — ratify?

RULE 4 · DROP RECENTSA manager manages

The rebuilt wallet quietly dropped its "what landed" list — the feed already shows that. Same argument here: the proof-faces status line still carries the first-connect "it works" moment, so the RecentThingsSection can go. Ask: drop it, or keep a peek?

What doesn't change

Every keyless promise and honesty line survives: read-only stated once (nav subtitle, not a footer wall), swipe-to-remove, the proof line on connect, per-account watch switches, bulk paste. No new capability — this is pure architecture.

Reach

9 bridges, ~2 components. Extract one LedgerRow + one Omnibox from the Farcaster rework; RSS and the four FeedFollow bridges inherit them almost free; Tokens/Stocktwits adopt in a follow-up sweep. Sequenced so the hardest screen (two-field Farcaster) proves the components first.

Law check: no hairlines (dividers are a whisper of type, the §83 rule); sentence case throughout; glass stays on the floating layer only (every row here is a fill); the tint washes are each bridge's own brand hue doing its one identity job. No dead controls — the profile card the rows tap into already exists and already does every action moved into it. The only new doctrine is square-for-topic (RULE 2), which generalizes the wallet's existing round/square grammar rather than inventing one.
