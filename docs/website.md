- RULE (user, 2026-07-08): every app added to the catalog ALSO lands on the website in the same session — (1) a tile in the hero marquee (`website/index.html`, the `.rain` div; continue the animation-delay sequence and keep `ai-more` last), (2) a `.mini-cell` in the `#catalog` section's matching shelf (rebuilt 2026-07-14 as packed shelf cards mirroring `AppsScreen.categories`; since 2026-10-26 a grid of category cards, largest first, each card's apps in the catalogue's order; ruling 2026-07-14: the website lists NO "Soon" apps — an offer the app can't connect simply isn't on the site), (3) an `.ai-<name>` brand background in `website/styles.css`. Then deploy: FIRST bump the `?v=` cache-busters on every page that links `styles.css`/`app.js` (index/features/docs) whenever those files changed — shipping new CSS/JS under an old `?v=` serves returning browsers yesterday's files against new markup (bare single-column catalog, invisible hero cards; paid for 2026-07-14). Then commit: since 2026-11-10 a push to main that touches `website/` publishes it to casberi.app through GitHub Pages (`.github/workflows/pages.yml`, which leaves out `mock-*.html` and any stray `.zip`), so the site changes only by a commit. The cPanel upload and the `~/Downloads/website-deploy.zip` rule (2026-07-14) are retired with the hosting. The domain is registered at Namecheap on BasicDNS (four A records to GitHub Pages, `www` CNAME to `alexanderchopan.github.io`, CAA for Let's Encrypt, DNSSEC on); `privacy@` is Namecheap email forwarding. Check the run with `gh run list --workflow pages.yml` — never leave the site trailing the app catalog.
- RULE (user, 2026-07-14): the app catalog, the website catalog, and the onboarding tiles stay in sync as ONE set, with **`BridgeCatalog.offers` (`Model/BridgeCatalog.swift`) the single source of truth**. Enforced by `scripts/catalog-sync.sh` (runs FIRST in `verify.sh`, exits non-zero on drift; pure static text check, no build needed — run it after any catalog/website/onboarding edit): (1) the website `#catalog` shelf lists EXACTLY the connectable offers, name-for-name — a connectable app missing from the site, OR a site tile that isn't a connectable offer (e.g. a removed app's leftover tile), fails; (2) the onboarding CONNECT rows are GONE (prd 96, 2026-07-16 — the connect screen died; connecting happens in the code-derived catalog); (3) the two DECORATIVE marquees — the website hero rain (`.rain`) and the onboarding rain (`IntroCover.marqueeApps`; it was `HowItWorksSheet.marqueeApps` until that sheet was deleted, prd §668) — stay hand-curated SUBSETS (ruling 2026-07-14: NOT forced complete — the hero has never shown Photos/Wallet/etc.; omissions are reported as info only), but every name they list MUST resolve to a real offer so a rename/removal can't leave a dead tile (this caught a leftover Telegram hero tile + an "Apple Podcasts"/"Podcasts" label mismatch on 2026-07-14). A marquee tile's `alt`/name must equal the offer name exactly (`"Podcasts"`, not `"Apple Podcasts"`).
- RULE (user, 2026-07-08): website icons are ALWAYS inlined as base64 data URIs in `website/index.html` — NEVER hot-link an external `<img src="https://cdn.simpleicons.org/…">` (or any remote image host). External icon hotlinks intermittently render as blank slots when the CDN hiccups / is rate-limited / is ad-blocked. To add an icon: fetch it from `cdn.simpleicons.org/<name>/ffffff` (or wherever), then inline the bytes as `data:image/svg+xml;base64,…` (or PNG base64). Every `<img>` on the site must be self-contained; there should be zero remote image requests.

## The docs page is the one source (2026-11-14)

- RULE: edit the docs in `website/docs.html` only, then run `python3 scripts/website-docs-audit.py --write`. `website/llms-full.txt` (the same text for a model) and the FAQ's structured data at the foot of the page are generated from it; `llms.txt` stays a hand-written summary. `--write` also sets "Describes Casberi x.y.z" from the project's `MARKETING_VERSION`.
- The audit fails the pass when the copies differ, when the two "Last updated" lines disagree, or when a retired word stands on any page or text file under `website/`. The words are `RETIRED` in the script, each with the ruling that retired it: add one there when the app stops saying a word.
- Why: by 2026-11-14 the plain-text copy was missing five things the page said, and "Library", "Threats" and "the slider" had stood on casberi.app for days after the app dropped them. The rule sheet has no line for this (it is at its size budget); the gate in `verify.sh` is the reminder.
- What the audit cannot do is say the docs are true. After a ruling that changes what a person sees, read the page.
