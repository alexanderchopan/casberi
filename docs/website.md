Then zip `website/` (exclude `mock-*.html` and any stray `.zip`) and push via Namecheap cPanel (File Manager → upload to the site root → Extract; see the web-deploy memory). RULE (user, 2026-07-14): whenever the deploy zip is rebuilt, ALSO place it at `~/Downloads/website-deploy.zip` — `rm` the old one first, then `cp` (a plain overwrite keeps Finder's old "Date Added", so the user can't find it at the top of Downloads). If the deploy can't be run from the session, prepare the zip and hand the user the exact steps — never leave the site trailing the app catalog.
- RULE (user, 2026-07-14): the app catalog, the website catalog, and the onboarding tiles stay in sync as ONE set, with **`BridgeCatalog.offers` (`Model/BridgeCatalog.swift`) the single source of truth**. Enforced by `scripts/catalog-sync.sh` (runs FIRST in `verify.sh`, exits non-zero on drift; pure static text check, no build needed — run it after any catalog/website/onboarding edit): (1) the website `#catalog` shelf lists EXACTLY the connectable offers, name-for-name — a connectable app missing from the site, OR a site tile that isn't a connectable offer (e.g. a removed app's leftover tile), fails; (2) the onboarding CONNECT rows are GONE (prd 96, 2026-07-16 — the connect screen died; connecting happens in the code-derived catalog); (3) the two DECORATIVE marquees — the website hero rain (`.rain`) and the onboarding rain (`IntroCover.marqueeApps`; it was `HowItWorksSheet.marqueeApps` until that sheet was deleted, prd §668) — stay hand-curated SUBSETS (ruling 2026-07-14: NOT forced complete — the hero has never shown Photos/Wallet/etc.; omissions are reported as info only), but every name they list MUST resolve to a real offer so a rename/removal can't leave a dead tile (this caught a leftover Telegram hero tile + an "Apple Podcasts"/"Podcasts" label mismatch on 2026-07-14). A marquee tile's `alt`/name must equal the offer name exactly (`"Podcasts"`, not `"Apple Podcasts"`).
- RULE (user, 2026-07-08): website icons are ALWAYS inlined as base64 data URIs in `website/index.html` — NEVER hot-link an external `<img src="https://cdn.simpleicons.org/…">` (or any remote image host). External icon hotlinks intermittently render as blank slots when the CDN hiccups / is rate-limited / is ad-blocked. To add an icon: fetch it from `cdn.simpleicons.org/<name>/ffffff` (or wherever), then inline the bytes as `data:image/svg+xml;base64,…` (or PNG base64). Every `<img>` on the site must be self-contained; there should be zero remote image requests.
