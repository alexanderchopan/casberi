# The Frames devnet

Moved out of `CLAUDE.md` on 2026-09-05 so the always-loaded file stays a rule sheet.
Every entry below is **verbatim** as it was written — nothing was summarised, shortened or dropped.
`CLAUDE.md` carries a one-line index pointing here, keyed by the hook flag or the entry title.

- **The Frames devnet (prd §548, 2026-09-01)** — `-framesProbe YES` (chain reach, chain id, head, gas price, this phone's balance and nonce), `-framesTxProbe <0x…>` (one transaction decoded frame by frame — mode, both budgets against what each used, per-frame status, payer), `-framesKeyProbe YES|claim` (the key's `presence=`/`address=`/`item=`/`orphaned=` triple, §531's blind spot; **`claim` is a WORD, not a flag** — the faucet allows one per source IP per hour, so a probe that spent it on every headless run is one nobody could put in a sweep). Chain **81410**, three keyless hosts `rpc{1,2,3}.frames.ethrex.xyz`, faucet `POST /api/claim {"address"}`. **The envelope is its own**: type `0x06` hashes **seven** fields with a scalar `nonce` and the three fees NESTED. Signing over a different field list yields a well-formed signature over a different digest that recovers to a real address (green build, correct screen, refused chain), so `FramesTransaction` is its own file with its own harness. Two more silent traps: the signature entry's `signer` is written **LITERALLY** (measured: literal 5/5, empty **0/5**), and a transfer carries a **real state budget**, never `stateGas: 0` (execution gas cannot pay for state growth, and a transfer to an address that does not exist yet grows state — the common case on a four-day-old devnet; with `state: 0` the frame halts on that write and burns its whole execution budget, reporting what reads as an execution failure). On the READ side a frame's execution budget is `gasLimit` — a reader that looks for another name gets nil, and a frame drawn with a nil budget looks like one that had none. **`stateGasUsed` is decoded OPTIONAL and never defaulted to zero**: `0x0` IS the discriminator that separates a missing STATE budget from a too-small EXECUTION one, so reading an absent field as zero asserts that diagnosis every time (`FramesRead.starvation` returns nil rather than judging). Measured absent on all 5 transactions, all of which are plain transfers that grow no state — the nightly row in `live-integrations.sh` watches for its arrival. `scripts/frames-tx-selftest.sh` compiles `FramesTransaction` WHOLE — two real on-chain vectors byte-exact with keccak matching the RPC's own hash, one synthetic with every field distinct (five near-identical real transactions cannot catch a field swap), 17 mutations. **IT SENDS, PROVEN AGAINST THE NODE (§548 amendment, same day).** A key was made, the faucet funded it, and a two-frame transfer was signed and broadcast — **the node returned our own predicted hash** (`0x9d12f772…`), which is the proof: the bytes we hashed are the bytes it hashed. Sent deliberately to a freshly generated address so the transfer GREW STATE, which settled the open question: **`stateGasUsed` does not exist on this client** even on that case, so the two-bar figure cannot be drawn and `FramesRead.starvation` correctly returns nil on every frame this chain produces today; the `live-integrations.sh` row watches for its arrival. **Second finding, unlooked-for: per-frame `gasUsed` does NOT sum to the transaction's** — 100 + 3,000 against a receipt of 210,790, so a room that adds its frames up and calls the total the cost is wrong by two orders of magnitude in the plausible direction; `FramesMove.gasUsed` is the receipt's own. **Wei is wider than `UInt64`** — the seat's first worked example holds 99,999.999762 ETH, which `UInt64(_:radix:)` returns nil for, so `FramesMoney` carries balances as raw hex through `Decimal` (rounding DOWN, no currency — test ETH has no price). The seat is **"Hegotá Frames"** (user's name), group Wallet, with `FramesScreen`, `FramesWatch`, `FramesLiveState`, the router destination, `AddressBook.Network.frames`, the bundled mark `brand-frames-devnet`, the website mini-cell, and a demo fixture of REAL measured figures that `demo-selftest` check M holds to its `installDemo`. **The account block LEADS the screen** — this chain holds 18 addresses, mostly genesis fixtures, so a pasted stranger's address shows a correct blank that reads as broken; `registerBridge` registers on the key OR the watch list for the same reason. **Still unbuilt: the room itself** (toggle row settled at Home · Frames · Activity · Sponsors) and its figures.



- **The Frames chain itself, and where a send is (prd §728, 2026-09-13)** — `-framesProbe YES` now also prints `framesChain| headAge= finalized= relaunchObserved= alert=`: the head's age against the ten-minute stall threshold, the node's own `finalized` block, the relaunch this install observed (a stored genesis baseline, never a shipped constant), and the headline Home would draw. It reads the chain even with nothing watched. `-framesPendingProbe <0x…>` asks EVERY host for one hash and prints `framesPending| host= sighting=absent|pooled|mined|no answer`, then the state the pending row draws for an old send with no deadline. **"no answer" is not "absent"**, and that is the separation the probe exists for: `dropped` needs every host to have answered null. The case that matters most — a hash every node has let go of — cannot be produced on demand. Measured while writing it: the chain had made no block for ~39 hours (head 75,685, 142,463s old), so a stalled chain is a real state rather than a hypothetical one.

- **The passkey account (prd §728d, 2026-09-13)** — `-framesPasskeyProbe YES` prints `framesPasskey| enclave= biometry= presence= account=` and then `code= nonce=` for the derived account. It never creates or signs: a key made by a probe is a Face-ID-bound key nobody chose. **Every simulator reports `enclave=NO`**, and that is the finding rather than a failure — no simulator can make or use this key, so the account's code and transaction shape are proven by `frames-tx-selftest.sh` and by the transactions that ran on chain 81410 (`0x176065d6…` deployed it, `0x7cb77ce7…` sent again without the deploy frame). `code=none yet` with a funded account is the healthy state before its first send.

- **More than one account on Frames (prd §774, 2026-09-16)** — every page of a wallet-family room draws its Actions — All for the current account, your own account for itself, a stranger's page `Create account` (Frames) or `Follow address` (Wallet) only; on Frames, where the key is the account, `FramesKey.createAnother()` mints a second item named by its address, lists it under `frames.signer.addresses`, and makes it current (`frames.signer.current`); `address()` is the CURRENT account, picked by its face on the rail (`select`, false for a stranger). The All page's Send row names the sender only when the phone holds more than one. `-framesKeyProbe` prints `held=N`. The first item's name and cached address are unchanged, so the §531 adoption guards in `frames-tx-selftest.sh` are the same lines. Not yet measured on a device.

- **The Frames seat moved to ethpandaops' `frames-devnet-0` (prd §962, 2026-09-27)** — chain **7034189865** (`0x1a3453829`), ONE public host `rpc.frames-devnet-0.ethpandaops.io` load-balancing geth, nethermind, reth and ethrex, explorer `dora.frames-devnet-0.ethpandaops.io`. **`FramesNetwork.current` is the one value** that names the chain — `FramesTransaction.chainID`, `FramesRPC.hosts`, the explorer and the faucet page all read it — because ethpandaops relaunches as `-1`, `-2` with a new id each time; a relaunch is one edit there plus re-pinning `live-integrations.sh`'s Frames block. **The envelope did not move**: the unchanged encoder re-encodes every distinct shape in 2,565 sampled transactions to the node's hash (vector D0 in `frames-tx-selftest.sh`). **Four things did**, all measured: (1) **the faucet is proof-of-work plus hCaptcha**, so Top up OPENS the page (`DevnetSendPanel.TopUp.opens`, the address copied first) and `FramesSend.claimFaucet` is deleted — `-framesKeyProbe` no longer takes `claim` and prints the page and the address instead; (2) **the validation prefix is capped at the spec's 100,000 of execution INCLUDING the signatures' cost (2,800 secp256k1, 6,700 P-256) and 500,000 of state** — 81410 allowed 500,000 and the VERIFY frame alone asked 100,000, so every send would have been refused; VERIFY frames ask 20,000, the passkey deploy 40,000 (measured ~19,000), the sponsor's paying frame exactly the 183,600 creation charge; `FramesSponsorRequest.currentFormat` is 2; (3) **about one read in four comes back bare** — a type-`0x06` transaction without `frames` or a receipt without `frameReceipts`, from the geth node behind the balancer (geth issue 35783) — so `FramesRPC.call` re-asks up to `bareRetries` (4) through `FramesRead.servesFrames`, never drawing a transaction with no frames; (4) **a Python `urllib` user agent is refused 403** by the endpoint (curl and CFNetwork pass) — set one in any script. A different stored chain id is a clean slate, never a "relaunched" alert (`FramesLiveState.forgetOtherNetwork`, keyed `frames.chain.network.v1`); keys and watched addresses carry over, and a DEMO's cached rows are kept because they are the fixture. `-framesStitchProbe` takes `|exec=N` / `|state=N` to starve every leg on purpose, which is how a failed frame's receipt was measured: **a state-starved and an execution-starved frame read the same** (status 0, execution used == budget, state 0), so `FramesRead.starvation` is deleted and `exhaustedBudget` names no cause. The app's send is proven there (`0x2e781e50…`, block 27,233), and the demo fixture is re-measured from this app's own sends.
