# The two devnets (Frames, vibenet, Hegota)

Moved out of `CLAUDE.md` on 2026-09-05 so the always-loaded file stays a rule sheet.
Every entry below is **verbatim** as it was written — nothing was summarised, shortened or dropped.
`CLAUDE.md` carries a one-line index pointing here, keyed by the hook flag or the entry title.

- **The Frames devnet (prd §548, 2026-09-01)** — `-framesProbe YES` (chain reach, chain id, head, gas price, this phone's balance and nonce), `-framesTxProbe <0x…>` (one transaction decoded frame by frame — mode, both budgets against what each used, per-frame status, payer), `-framesKeyProbe YES|claim` (the key's `presence=`/`address=`/`item=`/`orphaned=` triple, §531's blind spot; **`claim` is a WORD, not a flag** — the faucet allows one per source IP per hour, so a probe that spent it on every headless run is one nobody could put in a sweep). Chain **81410**, three keyless hosts `rpc{1,2,3}.frames.ethrex.xyz`, faucet `POST /api/claim {"address"}`. **It is NOT a Hegotá clone and the encoder cannot be shared**: both chains run ethrex and serve type `0x06`, and they hash DIFFERENT LISTS — Frames is **seven** fields with a scalar `nonce` and the three fees NESTED, Hegotá **eleven** flat with `nonceKeys`/`nonceSeq`/`recentRootReferences`. Signing with the wrong one yields a well-formed signature over a different digest that recovers to a real address (green build, correct screen, refused chain), so `FramesTransaction` is its own file with its own harness. Two more silent divergences: the signature entry's `signer` is written **LITERALLY** here where `HegotaSend` writes it EMPTY (measured: literal 5/5, empty **0/5**), and a transfer carries a **real state budget** where Hegotá sends `stateGas: 0` (execution gas cannot pay for state growth, and a transfer to an address that does not exist yet grows state — the common case on a four-day-old devnet; with `state: 0` the frame halts on that write and burns its whole execution budget, reporting what reads as an execution failure). On the READ side a frame's execution budget is `gasLimit` here and `executionGasLimit` on Hegotá — a reader written for one gets nil on the other, and a frame drawn with a nil budget looks like one that had none. **`stateGasUsed` is decoded OPTIONAL and never defaulted to zero**: `0x0` IS the discriminator that separates a missing STATE budget from a too-small EXECUTION one, so reading an absent field as zero asserts that diagnosis every time (`FramesRead.starvation` returns nil rather than judging). Measured absent on all 5 transactions, all of which are plain transfers that grow no state — the nightly row in `live-integrations.sh` watches for its arrival. The faucet's classifier is **shared, not forked** (`HegotaFaucetVerdict`, byte-identical wire shape incl. the bare 429). `scripts/frames-tx-selftest.sh` compiles `FramesTransaction` WHOLE — two real on-chain vectors byte-exact with keccak matching the RPC's own hash, one synthetic with every field distinct (five near-identical real transactions cannot catch a field swap), 17 mutations. **IT SENDS, PROVEN AGAINST THE NODE (§548 amendment, same day).** A key was made, the faucet funded it, and a two-frame transfer was signed and broadcast — **the node returned our own predicted hash** (`0x9d12f772…`), which is the proof: the bytes we hashed are the bytes it hashed. Sent deliberately to a freshly generated address so the transfer GREW STATE, which settled the open question: **`stateGasUsed` does not exist on this client** even on that case, so the two-bar figure cannot be drawn and `FramesRead.starvation` correctly returns nil on every frame this chain produces today; the `live-integrations.sh` row watches for its arrival. **Second finding, unlooked-for: per-frame `gasUsed` does NOT sum to the transaction's** — 100 + 3,000 against a receipt of 210,790, so a room that adds its frames up and calls the total the cost is wrong by two orders of magnitude in the plausible direction; `FramesMove.gasUsed` is the receipt's own. **Wei is wider than `UInt64`** — the seat's first worked example holds 99,999.999762 ETH, which `UInt64(_:radix:)` returns nil for, so `FramesMoney` carries balances as raw hex through `Decimal` (rounding DOWN, no currency — test ETH has no price). The seat is **"Frames Devnet"** (user's name), group Wallet, with `FramesScreen`, `FramesWatch`, `FramesLiveState`, the router destination, `AddressBook.Network.frames`, the bundled mark `brand-frames-devnet`, the website mini-cell, and a demo fixture of REAL measured figures that `demo-selftest` check M holds to its `installDemo`. **The account block LEADS the screen** — this chain holds 18 addresses, mostly genesis fixtures, so a pasted stranger's address shows a correct blank that reads as broken; `registerBridge` registers on the key OR the watch list for the same reason. **Still unbuilt: the room itself** (toggle row settled at Home · Frames · Activity · Sponsors) and its figures.

- `-vibenetCreateProbe YES` — what making a vibenet account WOULD do, without doing it (prd §530, 2026-08-30). Walks `VibenetSend.createAccount`'s own sequence up to — and deliberately NOT including — the signature: the contract map, this phone's key, the derived address, and what the payer says, ending on `wouldRefuse=`. It signs nothing, sends nothing and raises no Face ID prompt, so it can sit in a headless sweep (`-signerProbe`'s rule). It exists because a failed creation has SIX causes that render as one red sentence and only two are bugs: the config unreadable, no key on this phone, an address that will not derive, the faucet having nothing left, the payer service not answering, or the node genuinely refusing the bytes. **The address it prints is NOT a real creation's** — the salt is fixed at zero, exactly as `VibenetCreateSheet.draftAddress` does, because the real one is random per tap, which is also why an unsponsored creation can never succeed (nobody can fund an address nobody has seen) and is now refused BEFORE the prompt rather than after it. Both devnets' `broadcast` now carry the NODE'S OWN WORDS: the shipped placeholder "the node refused the transaction" named none of `insufficient funds` / `nonce too low` / `create address does not match the sender`, because `VibenetChain.call` maps a transport failure, a non-200 and a JSON-RPC `error` object all to nil — §515a's lesson in the write path. `IngestSupport.postJSONBody` is the load-bearing half: a node answers a rejected send with **HTTP 400 and the reason in the body**, and every other helper there gates the body on a 200.

- **The vibenet top up claims IN THE APP (prd §553b, 2026-09-01)** — `-vibenetFaucetProbe YES|claim`. `POST api.vibes.base.org/api/vibenet/faucet/drip` with `{"address"}`, MEASURED live: `200 {"tx_hash","amount_wei","to"}` (0.1 ETH), `429 {"error":"IP rate limited. Try again in 4s."}`, `400 {"error":"Invalid address"}`; `GET faucet/status` reports the terms and costs no cooldown (**`ip_cooldown_secs` and `addr_cooldown_secs` are both 10** — NOT Hegotá's hour, which is why `VibenetSendCard` words its own refusal instead of taking `HegotaFaucetVerdict.sentence`, guarded as a negative). **Same host the payer already uses, so nothing joins `NetworkReach`.** It exists because this room was wrong about its own faucet twice in one day, the same shape both times — **absence of a thing where we happened to look read as absence of the thing**: first an endpoint missing from OUR bridge read as a capability missing from the CHAIN (§553), then an endpoint missing from the SERVED HTML read as an endpoint that could not be found (§553's amendment, which shipped the tile as a Safari hand-off). The page is Next.js and its API client ships in the chunks the page loads; **"client-rendered" means the markup does not name the endpoint, never that the endpoint is unknowable.** `HegotaFaucetVerdict.ofDrip` is a second READER of one wire, not a second classifier — vibenet carries no `msg`, so `of`'s `said == "sent"` test can never fire and **every successful drip would classify as a refusal**; its one ordering divergence is that a body `error` is read BEFORE the hash (a body carrying both is contradictory, and refusing is the safe reading). The claim signs nothing — no key, no Face ID — which is what lets it fund an address the chain has never seen, so `FaucetRefusal` is its OWN error rather than a case on `VibenetSend.Failure` (every member of which is a way a SIGNED transaction fails, and adding one would put an unreachable case in two exhaustive switches). `DevnetSendPanel.TopUp.handsOff` is deleted with the hand-off it existed for. The two "Devnet faucet" rows keep the page deliberately: they are offered for any WATCHED undeployed address, and claiming silently on somebody else's behalf is not what that row promises. **`claim` is a WORD, not a flag** — bare `YES` reports and spends no cooldown; an empty Top up has five causes and only two are bugs, and `account=` is the line no screen shows. Guarded in `hegota-tx-selftest.sh` (8 assertions, 4 mutations on `ofDrip`, each anchored to something only that function contains — the two readers share three lines verbatim, so a loose pattern edits `of` and passes for the wrong reason) and `vibenet-selftest.sh` (7 drift guards, mutation-proven six ways). **UNMEASURED on a device**: the wire is measured, the tile has never been tapped on hardware.
