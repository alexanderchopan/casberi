- **EVERY POUR IS INK — `DS.pourInk`, one token, no exceptions (prd §524, 2026-08-29).** A card, a sheet head or a page gets a top the same way everywhere: `pourInk` → clear over 150pt (a page's own washes run longer), alpha baked into the adaptive colour so no view reads `colorScheme` for it. **`dsReceiptPaper` does not TAKE a colour** — the `Color?` whose nil meant "no pour" is gone, because a neutral makes no claim to opt out of and a paper without a top is the "jumble of text" §495 exists to fix. The rule that decides any new case: colour that says WHAT IS HAPPENING stays (the amount's tone, a stamp's ink, a mode disc, the connect bloom, the address face's reveal); colour that says WHERE IT CAME FROM goes, because the mark directly above the pour already says it at full strength. `DS.receiptPour`'s nine hues and `MoneyReceipt.Hue` still exist and are still harnessed — `DSStamp.shielded` is the one live caller, a word rather than a wash — so nothing here needs re-deriving if this is ever reversed. **UNSEEN on a device**: 0.078 was chosen against a mockup at the real tokens, so check it reads as a top rather than a band before trusting it.

- Honesty rule: no dead controls, no fake status. Three corollaries the 2026-07-16 audit paid for (prd §83): a hand-rolled button that paints its own background MUST swap that background when disabled — `.disabled` dims a plain-style button's label, not your background, so it reads live while inert (prefer `BridgeFieldRow`); never quote a price off a stale last trade — quote the live book's own bracket midpoint, or show nothing (an empty bid-0/ask-1 book is the one bracket that says nothing; its midpoint would invent a 50% coin flip), and read both sides of a delta the same way; and a change that rounds to zero has no direction — no sign, no green/red (`TokenChartStyle.isFlat` / `accent(change:)`). The iCloud-sync ship gate is MET (2026-07-07): CloudKit capability is in the build, voice audio rides the store (externalStorage → CKAsset), Delete everything purges the CloudKit zone, and only the app process mirrors (extensions use `SharedStore.extensionContainer()`). "End-to-end encrypted" claims still require Advanced Data Protection — don't overclaim.
- **THE MAC TAKES ITS OWN POINT SCALE — `DSTextStyle.macScale = 0.88`, one lever, no per-rung tuning (prd §631, 2026-09-06).** `TARGETED_DEVICE_FAMILY` includes family 6, so a point here is an AppKit point at 1:1 and the app's 17pt reading band rendered at a true 17 beside a system whose list text is 13. The ramp and `dsGlyph` both take the factor (a glyph holding its size while its label shrank breaks §359's icon↔label pairing); `DS.Face`/`DS.Mark` deliberately do NOT (a face is a picture and often a 44pt tap target, not type). The eleven `widget*` rungs opt out — a WidgetKit tile is the same size on both platforms — enforced as check 5 of `design-ramp-audit.py`. Safe unseen only because the direction is forgiving: smaller text inside a pinned frame leaves air, bigger text cuts. **UNSEEN on a Mac.**
- **The Mac's walked row can be TAKEN: ⌘C, Space (Quick Look), and drag-out (prd §631, `Shell/MacRowHandoff.swift`).** One resolver behind all three — the URL comes from `ShareTargetMemo`, so a row cannot copy one link and share another. ⌘C is safe because every `textSelection(.enabled)` site is in a sheet, a pushed room or the composer, all of which set `canWalk` false (measured, not assumed). Space is enabled only for screenshots and files, so on a link row it stays the scroll key. Drag is Mac-only on purpose: `.draggable` on touch IS the long-press the context menu already owns, and the pager claims every horizontal drag (2026-07-16). `KeyboardWalk` split into the RING and `WalkRowVerbs` because nine observers on one chain exceeded the type checker.
