# The agent — asks, BYOK, tools, the brief

Moved out of `CLAUDE.md` on 2026-09-05 so the always-loaded file stays a rule sheet.
Every entry below is **verbatim** as it was written — nothing was summarised, shortened or dropped.
`CLAUDE.md` carries a one-line index pointing here, keyed by the hook flag or the entry title.

- `-findProbe "<query>"` — fill the composer and fire **Find** (prd §215, the composer's deterministic door): runs `KeptAskComposers.search` → `Retriever.rank` and NSLogs `findProbe:` (query + the keepable kind) plus one `findDoc|` line PER doc line. Find is NOT the Ask button relabelled — no model is reached, nothing is synthesized, and the badge says "Matched on this iPhone — nothing was written"; a `findDoc|` dump carrying `Row(...)` entries and no prose IS that promise as a test. The chip leads the typed-draft band for ANY draft (a question included — "climate links" and "what did I save about climate?" are the same search to the retriever), while "Send to" keeps its old rule and sits out for a question. A paste offers no Find (a capture path on its way to being kept). The result is keepable straight into the `search:<query>` kind that already existed. One NSLog per line on purpose — a joined multi-line message gets truncated by the log reader (the `-todayProbe` lesson).

- `-openComposer YES` — open the composer empty (screenshots the ask chips); `-composerDraft "<text>"` — pre-fill the field on open (read in `Shell/Composer.swift`; reaches the typed state's "Open in" chips — the tool-tile grid and its `-forceTools` hook died 2026-07-16, prd 90); `-linkTitleProbe <url>` — NSLog the fetched page title; `-askStats "<key>:<n>[,…]|clear"` — seed the ask tiles' tap-learning decay counters (prd 95, `Model/AskMemory.swift`: an ask offered 10 opens untapped sorts behind the next qualifier; a tap resets it; seeded once per launch, self-guarded). Keys are MEMORY keys: the kind ("week", "pulse"), or kind:qualifier where one kind wears many faces ("showtag:recipes", "context:Photos"). Every composer open NSLogs `askTiles:` with the chosen keys, so demotion verifies in one launch (seed `pulse:12`, watch `pulse` move last). Opens that hand off an ask (chrome.askRequest) don't count as offers.

- Kept asks (docs/agent-brief.md rulings 1/4/5/13, `Model/KeptAskStore.swift`, `Model/KeptAskComposers.swift`) — the agent's own standing-question chips, always deterministic (never the model). `-keepAskProbe "<kind>:<title>"` keeps a kind headlessly (`clear` empties the store) — splits on the LAST colon (fixed 2026-07-20), since a compound kind carries its own (`showtag:Book club`, `context:Calendar`, `search:design links`). Kinds: `away`, `wallet`, `watchlist`, `overdue`, `noticed` (tile-only, no typed trigger), `showtag:<any tag>`, `context:<any connected source>` ("what's new in Calendar?"), `search:<query>` (any free-text ask that actually retrieved something — re-runs `Model/Retriever.swift`'s deterministic engine, painting matches, never re-synthesizing the original prose). `-agentThingProbe "<title prefix>"` pushes the agent's Stack straight to a real thing's drill-down headlessly (mirrors `-openThing`, title not UUID). `-askStats "<key>:<n>[,…]|clear"` — seed the ask tiles' tap-learning decay counters (prd 95, `Model/AskMemory.swift`: an ask offered 10 opens untapped sorts behind the next qualifier; a tap resets it). A KEPT pill shares these same counters (2026-07-20) and decay-DIMS instead of demoting, since it can't be sorted away. `-asksMade "<key>:<n>[,…]|clear"` — seed the INVERSE counter (how often an ask is actually made, not ignored): at `AskMemory.mintThreshold` (3) the answer's quiet "Keep" pill upgrades to a prominent "You ask this a lot — keep it?" prompt, same action underneath. Every composer open NSLogs `askTiles:` with the chosen suggestion keys, so demotion verifies in one launch (seed `pulse:12`, watch `pulse` move last). Opens that hand off an ask (chrome.askRequest) don't count as offers.

Grok (2026-07-31, prd §242) rides the OpenAI-compatible chat-completions shape (`api.x.ai/v1`), validated via a free `/v1/api-key` read; its pinned model id (`grok-4`) is UNVERIFIED — no key has ever been stored, so re-measure via `-byokProbe` before trusting it. - **The keyed agent got tools, a receipt, a model choice and a librarian (2026-08-06).** Until this date BYOK bought a better ANSWER on ONE screen, and was in three measurable ways weaker than the free path. **(1) Tools.** `AnswerTools` has made the on-device answer a real agent since 2026-07-15 (search the corpus, follow a lead with a second retrieval) while the paid path was a single-shot summarizer over one pre-retrieved candidate list — so the §307 complaint ("search my X stuff" answering with five unrelated things) reproduced on the path somebody PAYS for, where a second look costs a fraction of a cent. `Model/AgentCorpusTools.swift` declares three tools in all three wire shapes (Anthropic `input_schema`, OpenAI `function`, Gemini `functionDeclarations` — whose schema types are UPPERCASE, and a lowercase `string` is a 400 with no tool ever running), and `AgentAnswer.synthesize` runs a bounded loop (`maxRounds` 3 — a BILLING bound, not a capability one: every round re-sends the whole transcript, so round N costs ~N times the first; the last round declares NO tools, so the model is never handed one it won't be allowed to use). `list_sources` is the one that looks skippable and isn't — a model cannot filter by a source name it has never seen, and these names are the person's own connected apps. **Numbering is ONE space across both lists** (`Sink(reserved:)`): the prompt's candidates own 1…N and a tool hit is #N+1, or a `PICKS: 3` means two different things, and an ambiguous grounding row is a wrong one. **Redaction moved INTO the tools** — `synthesize` scrubs the candidates it was handed, but a tool result is corpus text fetched AFTER that gate, so it would have sailed past the tripwire entirely. Grounding rows put tool hits FIRST (a thing the model went and found is by construction one the retriever missed, so burying it would hide the only visible evidence the loop did anything). `ToolScore.rank` now forwards to `AgentCorpusTools.rank` — two copies of a retriever drift, and then the same question answers differently depending on whether a key is configured. **(2) Spend.** `Model/AgentSpend.swift` — settings has said "They bill you directly" since BYOK shipped, and nothing recorded a single request. It records **tokens, measured, and refuses to invent a price**: a per-model rate table renders perfectly whatever is in it and goes stale the day a provider re-prices, and a wrong number on a spending screen is believed; the one dollar figure shown is one the provider itself reported (OpenRouter's `/auth/key`). Usage is parsed per wire — Anthropic splits it across `message_start`/`message_delta`, Gemini rides `usageMetadata`, and the OpenAI shape reports it ONLY if asked, so `stream_options.include_usage` goes to OpenAI and OpenRouter (both document it) and NOT to Venice or Grok, where an unknown body key risks a 400 on the answer path itself — a missing spend row is far cheaper than a question that won't answer, and the screen prints its own sentence for a provider that reports nothing rather than a confident `0 in · 0 out`. Clearing a key forgets its receipt AND its model choice. **(3) Models.** `Model/AgentModels.swift` — the Grok pin shipped as `grok-4`, an id xAI's list does not contain, so every request would have failed the moment anybody added a key, and it was caught by READING hours later because no key existed to fail against; `gpt-4o`/`claude-opus-4-8` carry the same exposure with a slower fuse (a stale pin 404s, and the composer words that as ordinary trouble). The provider's own list is the authority, `defaultModel` is the fallback, and the filter is a DENYLIST of non-chat families rather than an allowlist of known-good prefixes — an allowlist silently hides the next model a provider ships, which is the failure this file exists to end. **(4) The librarian.** prd §282's five passes are all gated on `OnDeviceModel.isAvailable`, so on a device without Apple Intelligence that whole half of the product is a silent no-op — screenshots stay named "Screenshot" forever. `Model/AgentLibrarian.swift` lets a key do it: **opt-in, off by default** (the first path that would spend somebody's money on the app's own schedule), **the on-device model wins whenever it exists** (and its nil is FINAL — it returns nil for a deliberate NONE too, so paying to second-guess a correct decline is spending money to make the app worse), and bounded twice (the foreground sweeps keep their small limits; `catchUp` is capped and reports what it did). The §218 honesty rail (`ScreenshotNaming.grounded`) is MORE load-bearing here, not less — a bigger model is a better guesser, and fluency is what makes a wrong title unnoticeable. **(5) Per-ask provider** — `AgentKey.active` is app-wide, so four configured keys behaved like one; the keyed verb is now a `Menu` with a `primaryAction` (tap unchanged, long-press picks) and the choice persists for the open conversation, because `keyedHistory` threads prior turns that a different model didn't write. **(6) Past the composer** — `answerWithKey` had exactly ONE caller, so the moment you most wanted to ask about something was the one moment you had to leave and retype the subject; the thing sheet hands the ask to `ShellChrome.ask(_:withKey:)` rather than answering in place (one answer surface, one conversation, one place a keyed answer can be kept). Probes: `-byokProbe` now reports `model=` and `rounds=` (a tool loop and a single-shot summary produce identical-looking documents, so a doc dump alone cannot tell them apart) and prints the receipt after it; `-spendProbe YES` dumps the ledger per provider; `-modelsProbe YES` asks every configured provider what it offers and reports `pinStillReal=`; `-agentModel "<provider>:<id>"|clear` pins a model headlessly (declared BEFORE the probes — list order); `-librarianProbe YES` reports reachability and backlog **without spending**, and `-librarianProbe run` actually bills (a different word, not a flag — a probe that spends on every headless run is one nobody can safely put in a sweep). **All UNMEASURED against a live key** — no provider key is stored on this host. Every read fails safe, and the tool loop degrades to exactly the old single-shot behaviour on an empty `corpus`.

- **The keyed agent stopped re-paying for its own prompt, learned to read a saved page, and got a ceiling (2026-08-20, prd §415).** Three things, all on the key already configured. **(1) Prompt caching.** `AgentCorpusTools.maxRounds` is 3 as a BILLING bound — every round re-sends the whole transcript — and the expensive part was byte-identical each time (the synthesis contract, the tool schemas, sixteen numbered candidates, up to six screenshots). Two `cache_control` breakpoints now: one on the last content block of the current question (a breakpoint covers everything BEFORE it in render order — `tools` → `system` → `messages` — so that single mark caches all of it) and one on the last message of the conversation so far, which is what a follow-up re-reads instead of re-paying for. Two of the four allowed, deliberately: `steps` grows between rounds and must stay outside. **Anthropic ONLY, and the three silences differ**: ChatGPT and Gemini cache automatically with nothing to send (the hit is merely read back off `prompt_tokens_details.cached_tokens` / `cachedContentTokenCount`), and OpenRouter would need explicit breakpoints for an Anthropic-backed model but this app pins `openrouter/auto`, whose whole point is that the model is unknown to us — an unrecognized body key risks a 400 on the answer path, which is `stream_options.include_usage`'s exact reasoning. The saving lands on the receipt (`AgentSpend.cachedInputTokens`/`cacheWriteTokens`, both Optional — a non-Optional with a default would have failed the decode of every receipt on disk, the `RSSStore.Feed` trap in a second file) as a SHARE of the input total, never a figure beside it (every provider counts cached tokens INSIDE input) and never as dollars. **(2) Web fetch.** Anthropic's `web_fetch_20260318`, a SERVER tool — the API fetches inside the same request, so **no host of ours joins `NetworkReach`** and the round costs one request, not two. **What makes it usable is its own security rule: it can only fetch a URL that already appeared in the conversation**, so the reachable set is exactly the links this person saved and the tools chose to show — the grounding contract as a wire constraint. The URLs ride the TOOL RESULTS and deliberately NOT the candidate list (that list is shared verbatim with the on-device model — one contract, two engines — and a URL is ~20 tokens re-sent every round, so sixteen up front is money spent for a fetch usually not wanted); it follows that fetching is gated on the corpus tools being ON, since on the single-shot path there would be nothing in reach and every attempt is a guaranteed `url_not_in_prior_context`. `AgentWebFetch.fetchable` is a real gate: `Thing.content` holds `casberi://`, `obsidian://`, `file://`, `photos-redirect://`, signed CDN URLs (Instagram's `og:image` §395, Snapchat's §246) and private hosts off a self-hosted bridge — http/https only, no userinfo, no credential-shaped query key, no private host, nothing over the documented 250-char ceiling (a longer URL is a guaranteed `url_too_long`, so printing one buys an error), and the ORIGINAL string is returned since percent-encoding is not canonical. A link whose text `SecretScan` would alter is DROPPED, because a redacted URL is not safer, it is broken. Bounds are billing bounds with the arithmetic stated (2 pages, 12,000 tokens each; a research-paper PDF is ~125,000). **THE BUG IT WOULD HAVE INTRODUCED, caught before shipping**: the stream reader treated ANY `server_tool_use` block as a web SEARCH, correct only while search was the sole server tool — every page read would have lit "searched the web", a false provenance claim on the one line whose whole job is provenance (§83). The block's own `name` separates them, and a fetch is counted on its RESULT block so a refused fetch isn't counted as a page read. **(3) A monthly ceiling, OpenRouter only** (`AgentBudget`) — `AgentSpend` records tokens and refuses to price them, so a dollar cap is only sayable where the provider states dollars, and every other provider gets a sentence saying why there is no cap rather than a control that governs nothing. Three rules: the month's spend is a DELTA against a watched baseline (`data.usage` is a LIFETIME total, and a reading BELOW the baseline re-baselines too, since a lifetime total cannot go backwards); an unreadable figure NEVER pauses anything (not knowing ≠ knowing it's fine); and it governs the LIBRARIAN, never an ask (an ask is a tap — refusing it on a three-week-old setting is the dead control §83 bans; guarded as a NEGATIVE grep that `AgentBudget` never reaches `AgentAnswer`). A reached cap is a third state, not a failure: `canRun` going false landed on `.noKey`, whose sentence sends you to re-paste a key that was never the problem. **(4) The librarian runs on its OWN model** (`AgentTask`) — one pin per provider meant the frontier model somebody chose for hard questions was also naming screenshots hundreds of times over a backlog; `.ask` carries an EMPTY store suffix so an existing choice survives with no migration, and a librarian read falls back to the ASK choice before the pin. Probes: `-webFetchProbe "<url>|corpus"` (the link policy's verdict per URL, spending nothing), `-agentBudgetCap <usd|clear>`, `-agentLibrarianModel "<provider>:<id>"`, and `-byokProbe` now reports `pagesRead=` beside `rounds=`. Guarded by `scripts/agent-keyed-selftest.sh` (in `verify.sh`): `AgentWebFetch` compiled WHOLE, `AgentBudget`'s month arithmetic extracted by name, 13 mutations, drift guards read a COMMENT-STRIPPED copy (the source quotes the broken test verbatim — the Obsidian/Cursor lesson, sixth instance). **Its own first mutation finding is the standing lesson**: eight fixtures asserted a local-door scheme is refused and deleting the scheme check left all eight green, because every one was ALSO hostless or dotless and the host guard was doing the work — `ftp://files.example.com/…` is what makes that check load-bearing. **UNMEASURED against a live key**; every addition fails safe (an uncacheable prompt simply doesn't cache, a refused link is one the model never sees, an unreadable spend never pauses).

- **The agent rooms, past §367 (2026-08-20, prd §418) — and the fold that already existed.** Asked what would improve the ChatGPT/Claude/Codex experience, THREE of the proposals turned out to be built already: the Agents chip fold (§351 generalized Markets' fold into `CategoryFold` for EVERY category at `switcherFloor: 1`, and `Agents` holds all ten agent seats, so it has folded with a venue switcher and a remembered venue since that day) and the sheet's turn rendering (§367). **§412's lesson, third instance in one session: assuming absence from a grep, in a system more finished than the audit assumed.** The generalizable correction: before proposing a UI change to a mature room, read that room's most recent LEDGER ENTRY first — the code will not tell you which of its gaps were deliberate. **A DUPLICATE PARSER shipped in §415 and is deleted here**: `ChatTurns` read a transcript back into turns, which `AgentSheet.turns` had done since §367 and better (it derives the assistant's label from the SOURCE, where the duplicate held a closed vocabulary of three names, so a fifth agent seat would have been readable by one and invisible to the other) — written after grepping the importers and `ChatTranscript` but not for a sheet-side reader, and exactly the drift `ToolScore`→`AgentCorpusTools.rank` was folded to prevent. The two genuinely-new functions moved into `AgentSheet` beside the parse: `exchanges` (turns as (question, answer) PAIRS, the only shape `AgentTurn` has on any wire — an orphaned opening answer is DROPPED rather than given an invented question, consecutive asks pair the LATEST with the answer, and a trailing ask is returned as `pending` rather than folded into history) and `continuationInstructions`. **The ROW says how long the conversation was**: `messageCount` is stamped by all four importers, is in `FeedScreen`'s prefetch list (so it costs no fault), and was drawn on ONE screen in the app — a 61-turn session and a one-line question had identical chrome. It deliberately says nothing about the CLAMP, because knowing how much was cut needs the parsed turn count, i.e. reading `enrichedText`, a heavy column left out of that prefetch on purpose, for every row on every scroll; the sheet already carries that clause. The noun reads off `AgentSheet.assistant(for:)` rather than its own source list, so "turns" and "messages" can never disagree with the sheet. **CODE IS DRAWN AS CODE**: `NoteSheet.Block` gained `code(language:text:)` — drawn as prose a fence rendered its own backticks and, far worse, **every marker rule applied INSIDE the block**, so a Python `# TODO` became a heading and a shell `- flag` a bullet; the fence SUSPENDS all of them and that suspension is the case's whole content. **An unclosed fence still yields its code**, the common path rather than an edge one (an 8,000-char clamp routinely cuts a long answer's last fence mid-program). Extended rather than forked, so a vault note gains it free; `NoteProse` took a `tier` parameter (a turn is bubble-sized, a note body is `reading20` by §366) and **§366's guard MOVED WITH the rule** rather than being deleted — it now asserts the default plus that the note sheet never overrides it. The agent's side is markdown and the person's is not (§399's per-source FACT, and how these products themselves render). **"Carry on with Claude"** hands the turns to the keyed agent as history via `ShellChrome.askSeedHistory`, consumed exactly once in `keyedAnswerDocument` (the only place a keyed answer is composed) and cleared, so the next typed question can never inherit somebody else's chat; the model is told it is joining a conversation AND told when the transcript is clamped, since `cut` is the only place that fact exists. **It never invents a question** — it seeds the conversation's own pending ask when the transcript ends on you, else rises FOCUSED and empty, which closed a real hole: `consumeAskRequest` would have called `commit()` on an empty draft (the stranded-"Thinking…" failure its own neighbouring guard exists to prevent), and the only thing preventing it was that nothing had ever sent an empty `chrome.ask`. Guards in `note-sheet-selftest` (11 fence assertions, 3 mutations) and `agent-sheet-selftest` (pairing + continuation, 3 mutations). **A mutation caught a non-discriminating fixture for the THIRD time in one session** — `"use `let` here"` does not START with a backtick, so loosening the fence test to one backtick left the suite green; standing rule: **a fixture only tests the rule it names if it fails that rule and passes every other one.** UNMEASURED: no real export of any of these products has ever been held by this project.

- **External agents got two doors, and neither is a server (2026-08-06).** `MCPTools` has held three real tools since prd §34 and `MCPPairing` mints a real token, and none of it has ever been reachable — `transportReady` is false and the payload names a placeholder — because the design called for a SERVER and this product's whole claim is that it doesn't have one. **The way out is that it was never a server, it was a LISTENER**: `Model/MCPServer.swift` (Catalyst only) binds `NWListener` to 127.0.0.1 and speaks JSON-RPC over HTTP, so an agent on the SAME Mac (Claude Desktop, Claude Code, Raycast) reads the already-synced corpus with nothing hosted, nothing routed, and nothing leaving the machine. Four rails: loopback checked TWICE (the bind and the peer, because one is Apple's behaviour and one is ours), the pairing token required on every request (loopback is not authorization — a browser page is on loopback too), off by default, and **the write still routes through consent** (`save_thing` lands an approval-thing, and its result string is worded so the calling agent cannot report it as saved). It needs `com.apple.security.network.server`, which is a SANDBOX entitlement the app declares for itself — not a portal capability, so unlike FinanceKit it needs no profile change and cannot fail a signed archive; without it the listener never reaches `.ready`, which is why `lastError` is surfaced rather than logged (a failed bind and a switch nobody turned on look identical from outside). **UNMEASURED against a real MCP client, and structurally so** — it compiles out everywhere but Catalyst, so no simulator can exercise it; `transportReady` stays FALSE, no pairing UI claims a wire exists, and the Mac settings switch says plainly that it is unproven. The second door is the cheap one and by far the widest: `Model/AgentContext.swift` renders a thing (plus its neighbours, as TITLES only — one paste, not twenty documents) as markdown on the clipboard, with no API, no key, no network and no provider list, so it works with every agent that exists and every one that will, including the ones that have no API at all. Redacted on the way out, because a clipboard is the opposite of not leaving.

- `-todayProbe YES` — compose the **Today brief** (prd §166: the whisper's landing screen, and a keepable ask, `kind == "today"`) over the real corpus and NSLog the whole doc — every module chosen, every synthesis observation that fired. `Model/TodayBrief.swift`, deterministic.
