- **The journals' three shipped defects, fixed in the same pass (prd §398):** (1) **both importers silently truncated at 500 entries** — the §307/§309 class, in the two rooms nobody went back for; a journal is at most an entry a day, so 500 is thirteen months, and a truncated import and a complete one produced byte-identical receipts. `DayOneImport.entryCap` is 5,000 and the refusal is COUNTED (`Summary.dropped`, on the receipt, both screens and both probes, worded as X's "N older not imported"; named apart from `skipped` because "already here" is a re-import working and "not imported" is a run that left the oldest years on disk). Raising it tenfold created §310's risk, so both landings moved onto `ImportCommit` — a chunk is a commit, so a run that dies partway keeps what it landed. (2) **every note row read its first line twice** — `ExcerptRow` drew the title and then the whole of `content` beneath it, and every importer that names an entry after its opening line (Day One, Apple Journal, Obsidian, a shared Apple Note) stores that line as content's first line. **The guard for this existed and could never fire**: `text != thing.title` compares a raw body against `titleLine`'s flattened, 80-clamped, heading-mark-stripped output, which it almost never equals — and an entry whose first line ran past 80 characters could never match at all. `IngestSupport.bodyBelowTitle` is `titleLine`'s inverse and compares the NORMALISED first line. (3) **neither journal was in `ScreenshotTopics.topicSource` or `FeedInsight.topicMap`** — the two rooms in this app most literally "what you write about". Both registered (`.note`, `includeDomains: false` — §313's "a hostname is not a subject"), and the sweep runs from `BridgeRefresh` as well as at import, which is the half that matters: both importers dedupe on `sourceRef`, so healing only at import reaches nothing already imported (§320's lesson). **The journal exports' PHOTOGRAPHS land too** — Day One's `photos/<md5>.<type>`, Apple Journal's `Resources/` named by its HTML's `<img src>`, both as the same 480pt `ImportMedia` thumbnail every other picture here is. **Day One's picker accepts the FOLDER as well as the `.json`, and it has to**: a scoped grant on a file cannot read the directory beside it, so the `.json` pick could never have reached `photos/` whatever the parser did; both still import every entry and only the folder brings the pictures, which is the screen's one remaining slab note (Apple Journal's "Photos stay in the export for now" is DELETED, not reworded — it stopped being true and there is no choice left for fine print to govern). `ImportMedia.mediaIndex(in:under:)` is `xMediaIndex` generalised: ONE directory listing per import, keyed by basename WITHOUT the extension — not tidiness, since Day One's `type` is the export's word for the format and need not match the extension on disk, and Apple Journal's `src` depth is Apple's business. All UNMEASURED against a real export; every path fails safe (a stem that matches nothing yields no thumbnail and the row lands as before).
