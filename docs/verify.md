# The verification pipeline — audits, harnesses, perf

Moved out of `CLAUDE.md` on 2026-09-05 so the always-loaded file stays a rule sheet.
Every entry below is **verbatim** as it was written — nothing was summarised, shortened or dropped.
`CLAUDE.md` carries a one-line index pointing here, keyed by the hook flag or the entry title.

- **Mac parity gate (`verify.sh` step 1b, 2026-08-12):** after the iOS build, `verify.sh` COMPILES Mac Catalyst and hard-fails on any error. Until this landed the pass built iOS Simulator alone, so a mobile change that broke Catalyst went out green and was caught only by `verify-mac.sh` — a **LaunchAgent driving a real GUI app, so a closed lid means the night is SKIPPED, not queued** — or by a failing archive at ship time. Twenty-two files carry a `#if targetEnvironment(macCatalyst)` branch no iOS build ever compiles, and the ReownAppKit `platformFilter = ios` in the pbxproj (without it Catalyst dies on `'NSColor' is not a member type of class 'ReownAppKit.AppKit'`, measured 2026-08-01) is one careless project edit from gone with nothing else asserting it. **COMPILE ONLY, and that ceiling is the point** — it proves the Mac still BUILDS, never that it still WORKS; running it stays `verify-mac.sh`'s job and none of that script's plumbing transfers. Its OWN derivedData (`CasberiCatalystDD`), never `$DD`: a shared dir makes the two builds evict each other's module cache so every pass goes cold. Gates on xcodebuild's own exit, not on a bundle existing (verify-mac's 2026-08-01 lesson — an incremental dir keeps yesterday's bundle around). **Deliberately NOT spelled `xcodebuild … | grep error:` the way `verify-mac.sh` spells it**: that script runs `set -uo pipefail` and this one `set -euo pipefail`, so there a SUCCESSFUL build is what kills the run — grep matches nothing, exits 1, pipefail hands it to `set -e`. Measured 2026-08-12: **101s cold from an empty dir, 72s warm** (the warm number is the per-run cost). `SKIP_CATALYST=1` skips it, the `LAUNCH_CYCLES=0` hatch; it sits BEFORE the `--build-only` exit, so that flag is now a both-platform compile gate. Proven able to fail, since a check that cannot fail proves nothing: a `#if targetEnvironment(macCatalyst)` type error builds iOS clean (exit 0, 0 errors) while this goes red — green on iOS, broken on Mac, the entire class it exists for.

- **`verify.sh` runs `verify-mac.sh` IN PARALLEL and gates on it (user rule, 2026-08-21 — the two passes being separate was discovered, not chosen).** Launched in the background at the top of the pass (log: `<out>/verify-mac-parallel.log`), waited on as the LAST step: a red Mac run fails `verify.sh`, so one green now means BOTH platforms RUNNING, not just the Catalyst compile above. Wall time is max(iOS, Mac) and the Mac side (build + cold launches + probes + perf) is usually the long pole. Safe concurrently by construction, not hope: the derivedData dirs never overlap (`CasberiDD`/`CasberiCatalystDD` vs `CasberiMacDD`), every harness scratches through `mktemp`, and `verify-mac.sh` never touches the simulator; `LAUNCH_CYCLES`/`SKIP_LIVE`/`VERIFY_NO_CACHE` propagate through the environment, so one knob tunes both. `SKIP_MAC=1` opts out; `--build-only` never launches it (that flag is the compile gate and already covers the Mac half). Two edges handled and SAID rather than silent: if a `verify-mac.sh` is already running (the nightly, another session) the launch is skipped — a second run against the same `CasberiMacDD` would fight its build DB — and the closing line states the pass did NOT certify the Mac, repeated at the end because the launch-time note scrolled away fifteen minutes earlier; and an iOS failure REAPS the parallel Mac run (pid-scoped kill, never a bare pkill — `nightly-mac.sh`'s person-is-using-the-app lesson) since its verdict would describe a tree about to change. Proven able to fail before landing: a scratch mirror of the exact plumbing ran green-green, mac-red-fails-the-pass, iOS-red-reaps-no-orphan, and both skip paths. `nightly-mac.sh` still calls `verify-mac.sh` directly and is unaffected.

- **Mac parity audit (`scripts/mac-parity-audit.py`, 2026-08-12):** the drift a Catalyst COMPILE cannot see, and the answer to "must I flag new features for Mac parity" — **no**. Three checks, each derived from a REGISTRY IN THE SOURCE rather than a hand list, so a new screen/capability/shortcut is covered the day it lands. Static, self-tested (11 fixtures), in `verify.sh`; `verify-mac.sh` picks it up with no line of its own, because it is named `*-audit.py` and that script now discovers. **(1) Swept screens** — every `case "<host>"` in `RootShell.route(_:)` is a screen a deep link reaches, so both sweeps must open it or it goes in `KNOWN_UNSWEPT` with a reason. Found on its first run that **`casberi://settings` was swept on the Mac and never on iOS**: the screen carrying the privacy copy, the sync toggle and both delete verbs had no iOS screenshot in any automated pass (fixed by sweeping it, not exempting it). Three hosts are exempt with reasons: `brief` (it STREAMS for ~20-25s, so a 4s shot photographs a skeleton and certifies it as the screen), `person` (needs a handle already in the corpus) and `thing` (needs a real id; `-openThing` is its headless door). **Hosts on ONE `case` line are ONE screen** — `case "account", "apps":` is the catalog by its old name and its new one — and the first cut counted spellings instead, reporting `casberi://apps` unswept on both platforms while both sweeps were opening it as `casberi://account`; that false positive is now pinned by a self-test, since a lint that cries wolf gets turned off within a week. **(2) Entitlement decisions** — every key in a target's iOS entitlements must have a DECISION in its Catalyst sibling, present or in `KNOWN_IOS_ONLY` with a reason. NOT "must match": HealthKit/HomeKit/FinanceKit are unavailable on macOS by Apple's own declaration, so demanding equality demands a lie. This is the check with the longest fuse — an undecided capability costs nothing until a **signed Catalyst archive fails at ship time**, weeks later. **(3) The digit shortcuts** — ⌘1–⌘9 must stay positional against `chipOrder` (what the strip SHOWS, folded) and must resolve a folded category before writing `FeedFilter.source`; the raw write lands a category name where no predicate matches it, so the room is empty forever while the chip lights up as if it worked. **Mutation-proven against the real tree, not just fixtures**: one `case "vault":` added to the router is flagged on BOTH platforms, and one new key in `Casberi.entitlements` is flagged as undecided. **What it deliberately does NOT check** (compile parity plus these three is not "the Mac works"): a screen pushed via `HomeRoute.Node` rather than a deep link, a touch-only gesture with no pointer/keyboard path, and whether a swept screen actually looks right — the sweep proves a window mounted and painted >20KB, never that it painted the correct thing.

- **The two verify scripts each ran checks the other didn't, and both are now provably complete (2026-08-12).** Found while answering "does verify.sh keep Mac in parity"; the answer was no, and the drift ran BOTH ways because each script hand-copied the other's list. `verify-mac.sh` hand-listed **7** static audits while `verify.sh` ran 15, so `cloudkit-schema`, `design-motion`, `design-ramp`, `face-ramp`, `localization`, `prd-index`, `query-count-signal`, `setup-copy` and `demo-selftest` had **never run on that platform** while the pass printed "static audits ✓". It DISCOVERS them now — `scripts/*-audit.{py,sh}` is the registry, so the naming convention wires a new check in the day it lands (3 pre-convention names are listed explicitly; name a new one `*-audit.py` and it needs no line at all), and `--self-test` is REQUIRED of every discovered one rather than optional, since a check that can't demonstrate it catches anything certifies nothing. 16 audits, 9.5s. Conversely **7 self-tests had never run in `verify.sh`** — `address-safety`, `chatimport`, `claudecode`, `cursor-room`, `frontpage`, `keccak256`, `wallet-viz` — so the MAC pass had strictly more logic coverage than the iOS one; all seven now run, each with the comment saying what silent wrong answer it catches. **`verify.sh` keeps a HAND LIST on purpose and guards it instead of globbing** (step "Self-test completeness"): the comment above each harness is the only written record of why it exists, and a glob would run the same checks while throwing all of that away — so it is `catalog-sync.sh`'s shape, a curated set that must be provably complete. A new `*-selftest.sh` fails the pass until it is named WITH its reason, which is the point, because the reason is the part that gets skipped when nothing enforces it.

- **The pure-logic harnesses run at once, and an unchanged one is not re-run (PERF, 2026-08-19). Measured on full green passes: 32.8min → 15.2min → 3.6min.** Asked why a pass takes so long, the answer was not "the standard cost of good tests": the 51 harnesses in `verify.sh` are ~600 optimizing `swiftc` runs (each compiles its file WHOLE and mutation-tests it by editing a scratch copy and recompiling), and they ran **strictly one at a time on one core of eight**, with no caching — a phase that grew linearly with every harness added and had never been revisited since it was a handful. **(1) They run concurrently now** (`run_harnesses`, `xargs -P $(sysctl -n hw.ncpu)`), which is safe as a MEASURED property rather than a hope: every harness allocates its scratch through `mktemp`, so no two can collide on a path. **It is STILL A HAND LIST** — each `harness "…" "…" "scripts/x-selftest.sh" "…"` line names its script literally, so the "Self-test completeness" guard still finds it by grep and the comment above each line (the only written record of why that check exists) is untouched; a glob would run the same checks while throwing all of that away. **THE TRAP, paid for and worth remembering for any zsh script: job control is OFF in a non-interactive zsh, so `jobs -r` reports NOTHING** — the first cut used a `jobs -r` slot loop, which therefore degraded silently to "launch all 51 at once" and on 8 cores thrashes to SLOWER than serial while every check still passes. Green, and wrong; caught by measuring the wall clock, not by reading the code. `xargs -P` needs no job control. Output is now KEPT for every harness (generalizing the lesson `category-fold` bought on 2026-08-13 — two ~20-minute runs died having printed nothing but a ✗ because stdout went to `/dev/null`), and ALL failures are reported rather than the first, since under `fail`'s exit-on-first a second broken harness costs another full pass to discover. **(2) The skip cache** (`scripts/support/harness-key.py`): these harnesses are PURE, so one whose script and whose every named input are byte-identical to a run that PASSED has nothing new to say. The key is the harness whole + every repo file it NAMES whole + the swift version, and it is **the entire safety argument, because the failure mode is a FALSE GREEN** — a source that changed, a harness that was skipped, a ✓ printed over it. **Not just `.swift`**: `notify-selftest` reads both entitlements files, and the §383 rule it guards ("the code may claim the level only while the key is there") lives in the entitlements, not in Swift. **`scripts/` is in the set too** — `x-selftest` and `journal-room-selftest` carry drift guards that grep `scripts/verify.sh` ITSELF, so an edit to the room-head map there must re-run them; found by looking for the shape, not assumed absent, and the first pattern missed it entirely. Extraction is permissive and then filtered by what exists on disk, because **over-hashing is free and under-hashing is the bug**; measured, all 52 harnesses name their inputs as literal paths, and a harness yielding an EMPTY set is run unconditionally rather than trusted. **STATED CEILING, asserted as a self-test so it can never be mistaken for coverage:** this proves the harness's INPUTS are unchanged, never that the input SET is complete — a harness reading a source it never names would be under-covered. A failing harness is never stamped and its stale key is removed; the key's own `--self-test` runs FIRST every pass, because the cache decides which checks get skipped and so needs the proof this repo demands of every check. `VERIFY_NO_CACHE=1` disables it and **`nightly-mac.sh` exports it** — an unattended green is the one nobody re-reads — though note it is a BELT there rather than a fix: `verify-mac.sh`'s logic self-tests are its OWN DISCOVERED loop — deliberately a glob, not a hand list, so a harness added today runs tonight — which reads no cache and never will, since the whole point of that pass is that nobody is watching it. **That loop runs concurrently too now** (same `xargs -P`, same day): 52 harnesses, ~6–7min wall, long pole `wallet-rooms-selftest.sh` at ~3min, which is the floor no amount of parallelism goes below. It also KEEPS OUTPUT, which it never did — the old loop sent every harness to `/dev/null` and reported bare names, so a failed NIGHT said which harness broke and nothing about how, and re-running it by hand next morning is exactly the "passed standalone every time" dead end `category-fold` cost two ~20-minute runs to learn. **Running them concurrently immediately exposed a REAL bug that had been hiding in `ondevice-selftest.sh`, and the lesson generalises to any zsh script here: `cmd | grep -q X` under `pipefail` is a RACE.** `grep -q` exits 0 the instant it matches and closes the pipe; the writer — there a `sed` over a 2,800-line file — takes SIGPIPE and exits 141, and `pipefail` makes 141 the PIPELINE's status, so a following `&& echo` never fires. That guard therefore MISSED a matching file on an idle machine and caught it under load, same tree, same commit; a real third file taking its own `NLEmbedding` would have been swallowed identically. It was the second time that one guard was caught looking at nothing (the unquoted `--include` glob was the first). Read sed's output into a variable — no pipe, nothing to signal. The same pass also stopped it crying wolf: it flagged `DemoSeedAll` for NAMING `NLEmbedding` in demo row titles that are prose, so quoted strings are stripped now for the reason comments already were. The cache's STATE is always printed (`cache cold` / `N unchanged` / `cache OFF via VERIFY_NO_CACHE`), since "51 to run" otherwise reads identically whether the cache was cold or switched off. **Deliberately NOT done: `-O` → `-Onone` on the 84 compile sites.** It would be faster, but `retriever-selftest`'s own header records that a trapping harness under `-O` prints NOTHING — so the flag changes observable behaviour per harness and each would need checking; a blanket swap is exactly the green-and-wrong class above. Fixed in passing: **Radicle's ✓ was misplaced after Altana's**, so it had always reported out of order. Coverage is unchanged and CHECKED that way rather than assumed — the green-step sets were diffed across runs, all 136 prior steps present.

- **The pass ran every harness TWICE for eleven days (PERF, 2026-09-01). Measured on the 08-31 runs: 38–57min for a green pass, 154 and 161min for two overlapping sessions, against the 3.6min recorded above.** Asked why verifying takes longer and longer when the app is no more complicated, the answer was again not "the standard cost of good tests". The suite did grow — **52 → 86 harnesses in twelve days** — but the growth is not the story. **The 2026-08-21 parallel Mac leg made `verify.sh` launch `verify-mac.sh`, whose step-0b loop is a GLOB over `scripts/*-selftest.sh`, and then run the same 86 itself from its hand list — 172 executions for 86 checks, two `xargs -P ncpu` swarms on the same 8 cores, each slowing the other down.** Neither script could see the duplication: one deliberately globs and one deliberately hand-lists, so the two registries were never compared, and the entry above records them as separate loops for separate passes without noticing that one now starts the other. `SKIP_LOGIC=1` is set by `verify.sh` on the child it launches and by NOTHING else. **The safety argument is that these harnesses are pure and platform-independent BY CONSTRUCTION** — every one compiles a Foundation-only file, no UIKit, no simulator, no device — so the second run could only ever reach the same verdict more slowly. **What it costs, said rather than left to be discovered:** `verify.sh` runs its loop through the SKIP CACHE, so a harness cached there and skipped on the Mac runs in NEITHER leg of that pass; that is the cache's own bargain rather than a new hole (its key is the harness plus every input it names), and running it again on the Mac was accidental redundancy, never designed coverage. **The unattended passes are untouched, which is the whole of why this is safe**: `nightly-mac.sh` invokes `verify-mac.sh` DIRECTLY and sets nothing, and CI runs all 86 uncached on every push. Proven both ways before landing, against the REAL block extracted from the file rather than a retyped copy: `SKIP_LOGIC=1` prints the skip and executes ZERO harnesses, unset runs them and prints the slowest, and a deliberately-red fake harness still fails the pass — because a skip guard that cannot be shown to still fail is a switch for turning the checks off.
  - **THE PLAUSIBLE FIX WAS WRONG, and measuring it first is the lesson (the `-rankSweep` rule, second instance).** The proposed cause was cache invalidation: 13 harnesses name `CLAUDE.md`, which changes constantly, so every edit to this file would evict them. **Measured: `CLAUDE.md` has never been in any harness key at all** — `harness-key.py`'s `PATH` regex requires a `Casberi/`, `docs/`, `website/` or `scripts/` prefix, and a repo-root filename matches nothing. The companion proposal, stripping full-line comments before extracting inputs, moves **8 of 721 input edges and not one hot file**. Both were abandoned on the measurement, not argued about. **Build the cheap instrument before the plausible fix**: a 20-line python script over the real tree settled in one run what would otherwise have been a day's work on the wrong thing.
  - **The real cache story is FAN-OUT, and it is structural rather than a bug.** Measured mid-session: **23 harnesses cached, 63 to re-run**, and the blame is concentrated — `FeedScreen.swift` is a named input of **33** harnesses, `NetworkReach.swift` of 20, `ProbeHooks.swift` of 13, `ThingSheetView.swift` of 13. A harness names `FeedScreen.swift` for ONE grep drift guard and hashes all 8,900 lines of it, so any unrelated edit to the feed re-runs a third of the suite. That is the honest price of the guards being drift greps against whole files; narrowing the key to "the lines the harness greps for" would be a false-green machine and is deliberately NOT done. Two harnesses (`ondevice`, `room-perf`) have **never been stamped at all** — they have never passed under the cache — which is worth knowing, because a permanently-failing harness is also a permanent cache miss.
  - **Per-harness wall time is printed now, in both passes.** The suite grew by 34 harnesses with nothing recording what any one of them cost, so the only visible number was the total — **prd §257 exactly, applied to the test suite itself: a metric with no breakdown tells you to panic, not what to do.** Each child writes a `.sec` file and the runner prints the slowest 8. Contended under `xargs -P` and therefore not a clean per-harness cost, which is said in the comment; the ORDERING is what it is for, and it is stable across runs. A cached harness writes no `.sec` and correctly appears nowhere.
  - **Stale cache keys are pruned at 14 days.** The key covers every input, so one edit to a hot file leaves one dead stamp per harness naming it: **1,388 files for 86 harnesses when this landed, ~16 dead keys each**. Harmless, unbounded, and a directory nobody can read is a directory nobody will check.
  - **The nightly ledger is READ BACK at the top of every pass (REPORTS, never gates).** `nightly-mac.log` was written to and never opened, and **`nightly-mac` was RED on six of the last eight nights** with nobody the wiser. Sharper: **four of the five named failures already passed on the tree hours later** — so they were real at that commit and fixed during the following day, which means `main` was broken at push and nothing said so for up to twelve hours, IF the lid was open at all. It never gates, and that is not politeness: the verdict describes a DIFFERENT COMMIT, so failing today's pass over it would block work on a tree that may already carry the fix. Staleness is reported separately from failure, because a LaunchAgent driving a GUI app skips a closed-lid night rather than queueing it, and "no row since Tuesday" and "Tuesday passed" are different facts. Proven across all five cases (fresh pass, fresh fail, stale, unparseable row, no ledger).
  - **CI runs all 86 uncached on every push** (`.github/workflows/logic-selftests.yml`, macOS runner). `static-checks.yml` deliberately runs no `swiftc` harness — "a macOS runner is minutes and this is seconds" — and left them to two runners that both turn out to be unreliable in the same direction: the cache means `verify.sh` may skip one, and the nightly is a closed-lid LaunchAgent firing at 03:20 against whatever `main` happened to be. Discovered by glob, never enumerated. **UNVERIFIED against the runner's toolchain until its first run** — these harnesses are written against the local Xcode and a runner shipping an older Swift can fail one on syntax rather than on real drift; that surfaces as an ordinary failure on purpose, but read the first red run before assuming the code broke. `nightly-mac.sh` now parses `SUMMARY .*` rather than spelling each field, because an exact-field pattern silently matches NOTHING the day a field is added, which reads as a night with no summary — the gap that ledger exists to close.
  - **`-O` → `-Onone`, DONE for the four longest harnesses and mechanically provable for the rest (2026-09-02). The entry above was wrong to imply the cost was unknown.** **97% of a pure-logic harness's wall time is `swiftc`**, and the optimizer buys nothing an assertion can see. Measured per harness, both ways, over the same tree: **`wallet-rooms` 32.1min → 3.5min (9.2×), `hegota` 28.2min → 4.7min (6.0×), `vibenet` 47.0min → 7.6min (6.2×, converted 2026-09-02 in the §566 pass — it was not in the original four and was bigger than three of them), `walletbeat` 7.3 → 2.0 (3.6×), `l2beat` 5.6 → 1.7 (3.3×)** — 73 minutes to 12 on the long poles alone, and **the long pole is what sets the wall clock no matter how many cores the swarm gets** (measured the same day: 84 of 85 harnesses finished while one ran on alone for 28 minutes). **The recorded objection STANDS and is why this is per-harness rather than a `sed` over 81 files**: `retriever-selftest`'s own header records that a trapping harness under `-O` prints NOTHING, so the flag changes OBSERVABLE BEHAVIOUR, not merely speed. What the earlier entry left implicit is that "each would need checking" is a **MECHANICAL** check. **`scripts/support/harness-opt-probe.sh`** is it: run the harness both ways behind a `PATH` shim and compare output bytes and exit code — identical is the proof, anything else refuses the swap. The shim covers **`swiftc` AND `xcrun`**, since two harnesses go through the latter and would otherwise be measured UNCHANGED and reported safe on evidence that tested nothing. It edits no tracked file, so it runs safely beside a live session. **Two runs that fail IDENTICALLY report `n/a`, never "safe"** — equal output from two failures says nothing about the passing path, which is exactly the case `vibenet` hit while it was red. **Proven able to fail before it was trusted**: against a harness whose Swift traps it reports DIFFER, and the diff shows the recorded hazard itself — under `-O` the fatal error printed nothing at all, under `-Onone` it printed. **STATED CEILING**: it proves the two runs agreed on THIS tree today, so a harness that later grows a trapping mutation must be re-probed — which is why every converted site carries the reason and that instruction, and why the probe stays rather than being deleted once the conversion is done. **The zsh trap it cost on the way, worth remembering anywhere here: naming a variable `path` silently replaces `PATH`**, because lowercase `path` is its array form — every later `mktemp`/`cmp`/`diff` becomes "command not found".

- **The pass was mostly IDLE CORES, and the instrument came first (PERF, prd §612, 2026-09-05). Measured before touching anything: a cached harness phase ran ~6min of which the last ~4 were ONE harness on ONE core while seven sat idle; the room-head step spent ~90s on 28 COLD APP LAUNCHES; the Catalyst target was compiled TWICE per pass; and NO STEP IN THE PASS WAS TIMED.** Asked why verifying takes forever, the answer was again not "the standard cost of good tests" — the third recorded instance of that shape (§257, §318, and 2026-09-01's double-run). **`step()` is a clock now**: it closes the previous step before announcing the next, writes `<seconds>\t<name>` to `$OUT/step-times.tsv`, and the **EXIT trap** prints the slowest ten — from the trap rather than the bottom of the file, because a FAILED pass is exactly when you want to know where the fifteen minutes before the failure went. REPORTS, never gates (a threshold over a number that doubles on a busy machine is the flaky gate this repo avoids on purpose). **Read that report before aiming any further work at this suite; it is the item to keep if every other one here is reverted.**
  - **The mutation loops inside the long poles ran SERIALLY, and `xargs -P` ACROSS harnesses is what hid it.** The ten slowest each run 13–114 mutations one at a time, each a full recompile, so one file's serial loop set the whole pass's wall clock. `frames-tx-selftest.sh` had the fix since 2026-09-01 and it had never been carried to a sibling. Four ported (record, then fan out through a `--mutate` child in its own `mktemp` dir), CONTENDED numbers so they are floors: **vibenet 652s → 161s, hegota 472s → 48s, wallet-rooms 320s → 108s, privacy 250s → 94s.** **THE CHILD SITS AT THE VERY TOP OF THE FILE, above every line of setup** — one that re-ran the parent's preamble would re-run its assertion build too (114 compiles of vibenet's 4,000-line `main.swift`), which is slower than the loop it replaces. **THE COMPILE LINE IS WRITTEN ONCE into a `build.zsh` both halves run, and that is the load-bearing part**: every one of these files previously spelled its compile twice and vibenet spelled it FOUR times, which is exactly how §468 happened — one variant quietly omitted `$FACTS`, so every mutation it ran failed to compile and was **scored as caught**, thirty-four green checks testing nothing. Pristine sources are staged ONCE into `$spool/base/` and children copy from there, so an edit landing in the working tree mid-run (which happened during this very session — a concurrent checkout mid-edit on `HegotaSection.swift`) cannot make two mutations disagree about what "the shipped source" is. **Each port was proven able to fail three ways before it was trusted** — STALE (matches nothing), SURVIVED (an edited comment: changes the file, compiles, no assertion sees it), and a mutation declared BELOW the fan-out, which is a file-ORDER bug no care inside the block can catch — plus the arithmetic guard that **every recorded mutation must have reported**, since a child dying without a line is a mutation nobody ran.
  - **LONGEST FIRST, because the tail came back in a new place.** Measured after the ports: the full uncached suite ran **739s wall and the last 127s was `vibenet-selftest` alone**, having started near the end — `xargs -P` dispatches in the order it is fed, and both runners fed a NAME-ordered list (a hand list here, a glob in `verify-mac.sh`). The cost model is each harness's **own last recorded wall time**, kept beside the skip stamps and refreshed by whichever pass ran it; no hand list to drift, and a harness with no record sorts last. **A stale record errs harmlessly** — front-loading one that got faster just frees its slot early; the damage would be back-loading one that got slower, which stale data cannot do. Reporting still walks REGISTRATION order in both passes, because a pass whose lines reshuffle cannot be diffed against the last one.
  - **END TO END, full uncached suite of 93: the 2026-09-05 nightly ran 21m18s; the same suite after this pass ran 12m20s**, with one red — `wallet-permissions-selftest`, green on HEAD and red only in a working tree a concurrent session was mid-edit in. That is the HARNESS PHASE ALONE: it does not include the room-head collapse (~80s), the duplicate Catalyst compile (72s warm), or the build overlap, and the longest-first ordering landed after that run so it is not in the number either.
  - **TWO harnesses are NOT swapped, and the reasons differ.** `sweep-clock-selftest.sh` reports DIFFER and is **unprobeable by this method rather than unsafe**: its output carries wall-clock timings, PIDs and measured millisecond figures, so two runs of the SAME configuration differ too — both exited 0, and the swap was worth only 1.1× there because that harness is dominated by a deliberate 2-second sleep, not by the compiler. **That is the probe's own ceiling and it should be stated wherever the probe is trusted: it can only clear a harness whose output is DETERMINISTIC.** `wallet-permissions-selftest.sh` reports `n/a — both failed`, which is the probe refusing to call equal-failure equal-success; it is **GREEN on HEAD and RED only in the shared working tree** (a concurrent session mid-edit on `WalletSection.swift`), so it is a peer's WIP and not a break in `main` — re-probe it once that lands. Both keep `-O`.
